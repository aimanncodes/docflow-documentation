@@ overview | نظرة عامة على المحاسبة
@summary كيف تتدفق الأموال عبر DocFlow، وما يرحّله كل مستند، ومن يفعل ماذا، وكيف تُعدّ المحاسبة.

المحاسبة في DocFlow قائمة على القيد المزدوج وتعمل لحظياً. نادراً ما ترحّل إلى الأستاذ يدوياً، فالفواتير والمدفوعات وحركات المخزون والرواتب والإهلاك تنشئ قيودها بمجرد اعتمادها، فيبقى ميزان المراجعة محدّثاً دائماً، ويمكن تتبع كل رقم إلى المستند الذي أنشأه.

!fig مساحة عمل المحاسبة مع رسوم الذمم المدينة والدائنة والأرباح والخسائر

## كيف تتحول المستندات إلى قيود محاسبية

| المستند | مدين | دائن |
| --- | --- | --- |
| فاتورة المبيعات | المدينون | المبيعات، ضريبة المخرجات |
| فاتورة المشتريات | المخزون أو المصروف، ضريبة المدخلات | الدائنون |
| قيد الدفع (استلام) | البنك | المدينون |
| قيد الدفع (دفع) | الدائنون | البنك |
| إذن التسليم | تكلفة البضاعة المباعة | المخزون |
| إيصال الاستلام | المخزون | بضاعة مستلمة غير مفوترة |
| الرواتب | الرواتب | الرواتب المستحقة، الاستقطاعات |
| الإهلاك | مصروف الإهلاك | مجمع الإهلاك |
| قيد اليومية | أي حساب | أي حساب |

لا يمكن تعديل القيود المعتمدة، وتُصحح بالإلغاء (الذي يرحّل قيوداً عكسية) أو بإصدار إشعارات دائنة ومدينة. هذا الأستاذ غير القابل للتغيير هو ما يجعل DocFlow جاهزاً للتدقيق.

## من يفعل ماذا

| الدور | العمل اليومي المعتاد |
| --- | --- |
| Accounts User | إدخال الفواتير وتسجيل المقبوضات والمدفوعات |
| Accounts Manager | اعتماد القيود وتسوية البنوك وإقفال الفترات وإعداد إقرارات الضريبة |
| Auditor | صلاحية قراءة فقط لكل الدفاتر والتقارير |
| المدير العام | لوحات المعلومات والوضع النقدي والأرباح والخسائر |

## إعداد المحاسبة

1. راجع [دليل الحسابات](/accounting/chart-of-accounts) وأضف حساباتك البنكية.
2. عيّن الإعدادات المحاسبية الافتراضية للشركة و[إعدادات الحسابات](/accounting/accounts-settings).
3. أعدّ [مراكز التكلفة](/accounting/cost-centres-budgets) والأبعاد.
4. أعدّ قوالب [الضريبة](/uae-compliance/vat-setup) و[طرق الدفع](/accounting/mode-of-payment).
5. أنشئ قوالب [شروط الدفع](/accounting/payment-terms).
6. حمّل [الأرصدة الافتتاحية](/accounting/opening-balances).
7. رحّل معاملات تجريبية وراجع الأستاذ، ثم ألغها قبل بدء التشغيل.

## شهر نموذجي

1. تُرحَّل الفواتير يومياً.
2. تُسجَّل المقبوضات والمدفوعات عند حدوثها.
3. تُسوّى البنوك أسبوعياً.
4. تُرحَّل المستحقات والمدفوعات المقدمة والإهلاك في نهاية الشهر.
5. يُعدّ إقرار الضريبة في نهاية كل فترة ضريبية.
6. تُقفل الفترة وتُرسل التقارير إلى الإدارة.

:::uae مصمم لضريبة القيمة المضافة في الإمارات
يحمل كل مستند مبيعات ومشتريات قالباً ضريبياً، ويتتبع DocFlow ضريبة المخرجات والمدخلات والاحتساب العكسي منفصلة، ويملأ إقرار VAT 201 من معاملاتك. راجع [الامتثال في الإمارات](/uae-compliance/overview).
:::

:::details هل يمكن استخدام DocFlow للمحاسبة فقط دون المخزون؟
نعم. استخدم أصنافاً غير مخزنية لكل ما تشتريه وتبيعه، واترك **تحديث المخزون** دون تحديد، ويمكنك تفعيل المخزون لاحقاً.
:::

:::details أي معيار محاسبي يتبعه DocFlow؟
يسجّل DocFlow المعاملات، والمعيار خيارك. تعدّ معظم الشركات الإماراتية تقاريرها وفق المعايير الدولية، والدليل والتقارير الافتراضية مصممة على أساسها.
:::

@@ chart-of-accounts | دليل الحسابات
@summary افهم شجرة الحسابات، وأضف الحسابات ونظّمها، وعيّن أنواعها، وحافظ على نظافة الهيكل مع نمو أعمالك.

**دليل الحسابات** قائمة بكل حساب ترحّل إليه شركتك مرتبة كشجرة، وتُبنى منه التقارير كالميزانية العمومية والأرباح والخسائر، فالهيكل الواضح يجعل كل تقرير أسهل قراءة.

:::note قبل أن تبدأ
تحتاج إلى دور **مدير الحسابات** لتغيير الدليل، واتفق مع مدققك على التغييرات الهيكلية، ونفّذها قبل بدء التشغيل قدر الإمكان.
:::

## كيف تعمل الشجرة

- **المجموعات الجذرية** الخمس هي الأصول والخصوم وحقوق الملكية والإيرادات والمصروفات، ولا يمكن إعادة تسميتها أو حذفها.
- **الحسابات التجميعية** تنظّم حسابات أخرى، مثل *الأصول المتداولة › الحسابات البنكية*، ولا يمكن الترحيل إليها.
- **حسابات الأستاذ** تستقبل القيود، مثل *الإمارات دبي الوطني – جاري درهم*.
- ينتمي كل حساب إلى شركة واحدة، ولكل شركة في DocFlow دليلها الخاص.

!fig شجرة دليل الحسابات مع توسيع الأصول لإظهار حسابات البنوك والمدينين

## إنشاء الدليل

عند إنشاء شركة اختر أحد الخيارات:

| الخيار | متى تستخدمه |
| --- | --- |
| القالب القياسي | دليل نظيف وفق المعايير الدولية يناسب معظم الشركات الإماراتية |
| شركة قائمة | نسخ دليل شركة شقيقة لتقارير مجموعة متسقة |
| مستورد دليل الحسابات | رفع دليلك من جدول بيانات عند الترحيل |

### استيراد الدليل من جدول بيانات

1. انتقل إلى **المحاسبة › مستورد دليل الحسابات**.
2. اختر الشركة ونزّل القالب.
3. املأ صفاً لكل حساب: الاسم والحساب الأم والرقم وما إذا كان مجموعة والنوع الجذري ونوع الحساب والعملة.
4. ارفع الملف وانقر **تحقق**، وراجع الشجرة المعروضة وانقر **استيراد**.

يستبدل المستورد دليل الشركة، فلا تستخدمه إلا قبل ترحيل أي معاملات.

## إضافة حساب

1. افتح **المحاسبة › دليل الحسابات**.
2. انقر المجموعة الأم ثم **إضافة فرعي**.
3. أدخل **اسم الحساب** و**رقم الحساب** اختيارياً.
4. حدد **مجموعة** فقط إذا كان الحساب سيضم حسابات أخرى.
5. اختر **نوع الحساب** إن كان له سلوك خاص (انظر أدناه).
6. لحساب بنك أو طرف بعملة أجنبية، عيّن **عملة الحساب**.
7. انقر **إنشاء**.

## حقول الحساب

| الحقل | وظيفته |
| --- | --- |
| اسم الحساب | يظهر في التقارير، فاجعله قصيراً وواضحاً |
| رقم الحساب | رمز اختياري للترتيب، مثل 1110 للبنك الرئيسي |
| الحساب الأم | المجموعة التي فوقه |
| مجموعة | المجموعات تضم الحسابات، وحسابات الأستاذ وحدها تستقبل القيود |
| النوع الجذري | موروث من أعلى الفرع |
| نوع التقرير | الميزانية العمومية أو الأرباح والخسائر، موروث من الجذر |
| نوع الحساب | سلوك خاص في المعاملات (انظر أدناه) |
| عملة الحساب | عملة القيود، وتثبت بعد الاستخدام |
| نسبة الضريبة | النسبة الافتراضية لحسابات الضريبة |
| تجميد الحساب | يمنع القيود الجديدة |
| يجب أن يكون الرصيد | مديناً أو دائناً، ويحذّر عند انعكاس الرصيد |
| معطّل | يخفي الحساب من المعاملات الجديدة |

## هيكل مقترح لشركة تجارية إماراتية

| المجموعة | حسابات الأستاذ المعتادة |
| --- | --- |
| الأصول المتداولة › الحسابات البنكية | حساب لكل حساب بنكي وعملة |
| الأصول المتداولة › النقد | النقدية في الصندوق، النثرية لكل موقع |
| الأصول المتداولة › الذمم المدينة | المدينون بالدرهم، المدينون بالدولار، الشيكات المؤجلة المستلمة، دفعات مقدمة للموردين |
| الأصول المتداولة › أصول المخزون | المخزون المتوفر، البضائع في الطريق |
| الأصول المتداولة › المدفوعات المقدمة | الإيجار المدفوع مقدماً، التأمين المدفوع مقدماً، الرخص المدفوعة مقدماً |
| الأصول المتداولة › الضريبة القابلة للاسترداد | ضريبة المدخلات 5%، مدخلات الاحتساب العكسي |
| الأصول غير المتداولة | المركبات، المعدات، الأثاث، تحسينات المباني المستأجرة، مجمع الإهلاك |
| الخصوم المتداولة › الذمم الدائنة | الدائنون بالدرهم، الدائنون بالدولار، الشيكات المؤجلة الصادرة، دفعات مقدمة من العملاء |
| الخصوم المتداولة › الرسوم والضرائب | ضريبة المخرجات 5%، مخرجات الاحتساب العكسي، الضريبة المستحقة، ضريبة الشركات المستحقة |
| الخصوم المتداولة › المستحقات | الرواتب المستحقة، المصروفات المستحقة، مخصص تذاكر السفر |
| الخصوم غير المتداولة | مخصص مكافأة نهاية الخدمة، القروض طويلة الأجل |
| حقوق الملكية | رأس المال، الاحتياطي القانوني، الأرباح المحتجزة، الحسابات الجارية للشركاء |
| الإيرادات | مبيعات البضائع، مبيعات الخدمات، إيرادات أخرى |
| المصروفات › تكلفة المبيعات | تكلفة البضاعة المباعة، الشحن الداخلي، الرسوم الجمركية |
| المصروفات › تكاليف الموظفين | الرواتب، المكافأة، تذاكر السفر، تكاليف التأشيرات والعمل، التأمين الطبي |
| المصروفات › المباني | الإيجار، الكهرباء والمياه، الصيانة |
| المصروفات › الإدارية | الاتصالات، الرخص والتصاريح، الأتعاب المهنية، الرسوم البنكية |

:::uae الاحتياطي القانوني
قد تُلزم بعض الشركات الإماراتية، بموجب عقود تأسيسها أو القانون المنطبق، بتحويل نسبة من الأرباح السنوية إلى احتياطي قانوني حتى يبلغ نسبة محددة من رأس المال، فاحتفظ بحساب **احتياطي قانوني** منفصل ليظهر التحويل.
:::

| التغيير | مسموح؟ | الطريقة |
| --- | --- | --- |
| إعادة تسمية حساب | نعم | افتح الحساب وأعد تسميته |
| تغيير رقم الحساب | نعم | عدّل الحقل |

## مشكلات شائعة

:::details "لا يمكن تحويل حساب الأستاذ إلى مجموعة لوجود معاملات"
أنشئ مجموعة جديدة بالاسم الذي تريده، وانقل الحساب تحتها، ثم أعد التسمية حسب الحاجة.
:::

:::details حساب بنكي جديد لا يظهر في قيود الدفع
تحقق من أن **نوع الحساب** بنك وأنه يتبع الشركة الصحيحة، ثم أضفه إلى [طريقة دفع](/accounting/mode-of-payment).
:::

:::details ترتيب الشجرة يبدو غير صحيح
تتحكم أرقام الحسابات في الترتيب، فأضف الأرقام، أو انقر **إعادة بناء الشجرة** إذا بدا الهيكل تالفاً بعد استيراد كبير.
:::

@@ sales-invoice | فواتير المبيعات
@summary كل ما يتعلق بفوترة العملاء: كل قسم في النموذج، وكل نوع من الفواتير، والمحاسبة خلفها، وحل المشكلات الشائعة.

**فاتورة المبيعات** هي المستند الذي يخبر عميلك بالمبلغ المستحق عليه وينشئ الذمة المدينة في دفاترك، وهي في الإمارات أيضاً **فاتورتك الضريبية**، فيجب أن تحمل البيانات التي يشترطها قانون الضريبة. كل عملية بيع، سواء كانت بضائع أو خدمات أو عربوناً أو بيعاً نقدياً أو إعادة تحميل لشركة في المجموعة، تنتهي بفاتورة مبيعات.

:::note قبل أن تبدأ
- يوجد العميل برقم ضريبي (إن كان مسجلاً) وعنوان فوترة محددة فيه الإمارة وشروط دفع.
- توجد الأصناف بحساب إيرادات، ومخزون كافٍ في المستودع للأصناف المخزنية.
- أُعدّت قائمة أسعار بيع وقالب ضريبي. راجع [إعداد ضريبة القيمة المضافة](/uae-compliance/vat-setup).
- يتضمن دورك **Accounts User** (أو **Sales User** مع صلاحية إنشاء الفواتير)، وقد يقيَّد الاعتماد بـ[سير عمل](/framework/workflows).
:::

## أنواع فواتير المبيعات

نموذج واحد يغطي حالات عدة، وبضعة اختيارات تغيّر سلوكه.

| النوع | طريقة إنشائه | ما يختلف |
| --- | --- | --- |
| فاتورة عادية | من أمر بيع أو إذن تسليم أو جديدة | تنشئ ذمة مدينة، وينقل إذن التسليم المخزون |
| فاتورة بتحديث المخزون | حدد **تحديث المخزون** | تخفض المخزون أيضاً فلا حاجة لإذن تسليم |
| بيع نقدي أو بالبطاقة | حدد **نقطة بيع** أو استخدم [نقطة البيع](/accounting/pos) | تُسجَّل الدفعة في الفاتورة نفسها |
| إشعار دائن | **إنشاء › مرتجع / إشعار دائن** من فاتورة | كميات سالبة، يخفض الذمة وضريبة المخرجات |
| إشعار مدين لعميل | حدد **إشعار مدين** مقابل الفاتورة الأصلية | يحمّل مبلغاً إضافياً كزيادة سعر أو شحن فائت |
| فاتورة افتتاحية | [أداة إنشاء الفواتير الافتتاحية](/getting-started/data-import) | تُرحَّل إلى حساب افتتاحي مؤقت عند بدء التشغيل |
| فاتورة بين الشركات | البيع لعميل داخلي | تنشئ فاتورة مشتريات مطابقة في شركة المجموعة ([الدليل](/accounting/inter-company)) |
| فاتورة من سجلات الوقت | **جلب سجلات الوقت** في الفاتورة | تفوتر الساعات المسجلة على المشاريع ([الدليل](/projects/timesheets)) |
| فاتورة اشتراك | ينشئها [اشتراك](/accounting/subscriptions) | تُنشأ تلقائياً كل فترة |

## ثلاث طرق لإنشاء الفاتورة

1. **من أمر بيع**: افتح الأمر وانقر **إنشاء › فاتورة مبيعات**، واستخدمها للفوترة المقدمة أو للخدمات دون تسليم.
2. **من إذن تسليم**: افتح الإذن وانقر **إنشاء › فاتورة مبيعات**، وهي الطريقة المعتادة للبضائع، ولا تُجلب إلا الكميات المسلّمة.
3. **مباشرة**: انتقل إلى **المحاسبة › فاتورة المبيعات › جديد**، للخدمات لمرة واحدة أو إعادة التحميل أو مبيعات الكاونتر.

لفوترة عدة أذونات تسليم للعميل نفسه معاً، ابدأ فاتورة جديدة واختر العميل ثم انقر **جلب الأصناف من › إذن التسليم** وحدد الأذونات المطلوبة.

!fig جلب الأصناف من عدة أذونات تسليم إلى فاتورة مبيعات واحدة

### الضرائب والرسوم

اختر **قالب ضرائب ورسوم المبيعات**، وعادةً *ضريبة القيمة المضافة 5%*، فيمتلئ الجدول بصف أو أكثر، ولكل صف **نوع** يحدد طريقة الاحتساب.

| النوع | الاحتساب | الاستخدام المعتاد |
| --- | --- | --- |
| على صافي الإجمالي | النسبة × صافي الإجمالي | الضريبة 5% |
| فعلي | مبلغ ثابت تكتبه | الشحن، المناولة، رسوم بلدية |
| على مبلغ الصف السابق | النسبة × مبلغ صف سابق | ضريبة على رسم |
| على إجمالي الصف السابق | النسبة × الإجمالي التراكمي حتى صف سابق | ضريبة على صافي الإجمالي زائد الشحن |
| على كمية الأصناف | النسبة × الكمية الإجمالية | رسم لكل وحدة |

حدد **هل هذه الضريبة مشمولة في السعر الأساسي؟** في صف الضريبة عندما تشمل أسعارك الضريبة كما في التجزئة، فيستخرج DocFlow الضريبة من داخل السعر.

:::uae رسوم التوصيل خاضعة للضريبة أيضاً
إذا أضفت الشحن كصف *فعلي*، فأضف الضريبة عليه أيضاً باستخدام **على إجمالي الصف السابق** لصف الضريبة، أو أضف الشحن كصنف خدمة ليغطيه قالب الضريبة.
:::

!fig جدول الضرائب والرسوم مع ضريبة 5% ورسم شحن

### شروط الدفع وجدوله

يبني **قالب شروط الدفع** جدولاً بتواريخ الاستحقاق والمبالغ، فمثلاً قالب 30/70 على فاتورة بقيمة 100,000 درهم ينشئ صفين: 30,000 درهم عند الفاتورة و70,000 درهم خلال 60 يوماً، وتستخدم تقارير الأعمار و[المطالبات](/accounting/dunning) تاريخ استحقاق كل صف. راجع [شروط الدفع](/accounting/payment-terms).

### العناوين وجهات الاتصال

| الحقل | وظيفته |
| --- | --- |
| عنوان العميل | عنوان الفوترة المطبوع مع الرقم الضريبي، وتحدد إمارته خانة إقرار الضريبة |
| عنوان الشحن | مكان تسليم البضاعة |
| جهة الاتصال | من تُرسل إليه الفاتورة |
| عنوان الشركة | عنوانك المطبوع مع رقمك الضريبي |
| عنوان الإرسال | مكان خروج البضاعة إن كان مختلفاً |

### الشروط وفريق المبيعات وتفاصيل أخرى

- **الشروط والأحكام**: قالب أو نص حر يُطبع في النهاية.
- **فريق المبيعات** و**شريك المبيعات**: من يُنسب إليه البيع والعمولة ([الدليل](/selling/sales-partners)).
- **برنامج الولاء**: النقاط المكتسبة أو المستبدلة ([الدليل](/accounting/loyalty-program)).
- **المشروع**: يربط الإيراد بمشروع.
- **الترويسة** و**عنوان الطباعة** و**لغة الطباعة**: تتحكم في شكل الفاتورة، مثل عنوان "فاتورة ضريبية" ولغة طباعة عربية.
- **الملاحظات**: ملاحظات داخلية لا تُطبع إلا إذا تضمنها تنسيقك.

## سيناريوهات عملية

:::example الفوترة الجزئية لأمر بيع
يطلب فندق 10 ثلاجات لكنه يستلم 6 هذا الشهر. أنشئ الفاتورة من إذن التسليم فلا تُفوتر إلا الستة المسلّمة، ويبقى أمر البيع **للتسليم والفوترة** للأربع المتبقية.
:::

:::example دفعة مقدمة قبل الفاتورة
تستلم صقر للحديد 52,500 درهم (50% زائد الضريبة) دفعة مقدمة لطلب رفوف، وتُقرّ الضريبة على الدفعة عند استلامها. عند إصدار الفاتورة النهائية بقيمة 105,000 درهم انقر **جلب الدفعات المقدمة المستلمة** وخصّص 52,500 درهم، فتعرض الفاتورة 52,500 درهم مستحقة.
:::

:::example تصدير إلى عُمان بنسبة الصفر
تبيع الواحة للتجارة معدات مطابخ بقيمة 20,000 دولار لفندق في مسقط. الفاتورة بالدولار بسعر 3.6725 (73,450 درهماً)، وتستخدم قالب **نسبة الصفر**، وتُرفق شهادة الخروج بإذن التسليم دليلاً.
:::

:::example أسعار تشمل الضريبة في صالة العرض
يشتري زائر خلاطاً سعره 1,050 درهماً شاملاً الضريبة، ومع تحديد **هل هذه الضريبة مشمولة في السعر الأساسي؟** تعرض الفاتورة صافياً 1,000 درهم وضريبة 50 درهماً.
:::

## ما يحدث خلف الكواليس

**فاتورة عادية** بقيمة 37,000 درهم زائد الضريبة:

| الحساب | مدين | دائن |
| --- | --- | --- |
| المدينون – العميل | 38,850 | |
| مبيعات البضائع | | 37,000 |
| ضريبة المخرجات 5% | | 1,850 |

**مع تحديث المخزون** يرحّل قيد ثانٍ تكلفة البضاعة (ولتكن 24,000 درهم):

| الحساب | مدين | دائن |
| --- | --- | --- |
| تكلفة البضاعة المباعة | 24,000 | |
| المخزون المتوفر – المستودع | | 24,000 |

**بيع بنقطة البيع مدفوع بالبطاقة** بقيمة 1,050 درهماً شاملاً الضريبة: يُجعل حساب تسوية البطاقات مديناً بمبلغ 1,050 درهماً بدلاً من المدين، وتُجعل المبيعات 1,000 درهم وضريبة المخرجات 50 درهماً دائنة.

**شطب** 0.35 درهم عند الدفع: حساب الشطب مدين والمدينون دائن.

## الطباعة والإرسال والفوترة الإلكترونية

1. انقر **طباعة**، واختر تنسيق **الفاتورة الضريبية الإماراتية** وترويستك، وعيّن **لغة الطباعة** إلى العربية أو الإنجليزية أو كلتيهما.
2. انقر **بريد إلكتروني**، واختر [قالب بريد](/framework/email-templates)، وأرسل ملف PDF إلى مسؤول حسابات العميل.
3. عند تفعيل [الفوترة الإلكترونية](/uae-compliance/e-invoicing)، يرسل اعتماد الفاتورة نسخة منها أيضاً عبر شبكة DocFlow، وتبيّن حالتها ما إذا قُبلت.

## مشكلات شائعة

:::details "تم تجاوز حد الائتمان للعميل"
الرصيد المستحق على العميل زائد هذه الفاتورة يتجاوز حده، فيمكن لمستخدم بدور مراقب الائتمان اعتمادها، أو سجّل دفعة أولاً.
:::

:::details "أمر البيع مطلوب للصنف"
تشترط إعدادات المبيعات أمر بيع، فأنشئ الفاتورة من الأمر أو اطلب من المسؤول تغيير الإعداد.
:::

:::details "مخزون غير كافٍ" مع تحديث المخزون
المستودع لا يحتوي على الكمية، فألغِ تحديد **تحديث المخزون** وسلّم لاحقاً بإذن تسليم، أو انقل المخزون أولاً.
:::

:::details الرقم الضريبي للعميل لا يُطبع
لا يوجد رقم ضريبي للعميل، أو يستخدم تنسيق الطباعة حقلاً آخر، فأضف الرقم للعميل وأعد الطباعة دون إلغاء.
:::

:::details الضريبة تختلف بفلس عن حساب العميل
يقرّب DocFlow على مستوى الفاتورة افتراضياً، فإذا كان العميل يحسب لكل سطر فاتفقوا على الطريقة أو غيّروا إعداد تقريب الضريبة.
:::

:::details أحتاج إلى تغيير فاتورة معتمدة
يمكن تغيير الحقول المحددة بـ**السماح عند الاعتماد**، كالملاحظات أو رقم أمر شراء العميل، أما غيرها فألغِ وعدّل إن كانت الفترة مفتوحة ولم تُرسل الفاتورة، أو أصدر [إشعاراً دائناً](/accounting/credit-debit-notes).
:::

## أنواع فواتير المشتريات

| النوع | طريقة إنشائه | ما يختلف |
| --- | --- | --- |
| فاتورة بضائع عادية | من إيصال استلام أو أمر شراء | تصفّي *البضاعة المستلمة غير المفوترة* |
| فاتورة بتحديث المخزون | حدد **تحديث المخزون** | تستلم المخزون دون إيصال منفصل |
| فاتورة مصروف | فاتورة جديدة بأصناف مصروفات | تُرحَّل مباشرة إلى حسابات المصروفات |
| مدفوعة فوراً | حدد **مدفوعة** | تسجّل الدفعة في الفاتورة للمشتريات النقدية أو بالبطاقة |
| إشعار مدين | **إنشاء › مرتجع / إشعار مدين** من فاتورة | يخفض المستحق وضريبة المدخلات |
| استيراد خدمات | قالب الاحتساب العكسي | يرحّل ضريبة المخرجات والمدخلات معاً ([الدليل](/uae-compliance/reverse-charge)) |
| فاتورة بين الشركات | تُنشأ من فاتورة مبيعات لشركة في المجموعة | تطابق فاتورة البائع ([الدليل](/accounting/inter-company)) |
| فاتورة افتتاحية | أداة إنشاء الفواتير الافتتاحية | تحمّل الفواتير غير المسددة عند بدء التشغيل |

## ثلاث طرق لإنشاء فاتورة المشتريات

1. **من إيصال استلام**: افتح الإيصال وانقر **إنشاء › فاتورة مشتريات**، وهي الطريقة المعتادة للبضائع وتمنحك مطابقة ثلاثية.
2. **من أمر شراء**: للخدمات أو الدفعات المقدمة حيث لا يوجد إيصال.
3. **مباشرة**: **المحاسبة › فاتورة المشتريات › جديد**، للمرافق والإيجار والاتصالات والفواتير الأخرى دون أمر.

لفوترة عدة إيصالات من مورد واحد معاً، ابدأ فاتورة جديدة واختر المورد واستخدم **جلب الأصناف من › إيصال الاستلام**.

### الضرائب والرسوم

اختر **قالب ضرائب ورسوم المشتريات**: *ضريبة المدخلات 5%* للموردين المحليين، و*الاحتساب العكسي* للخدمات المستوردة وضريبة الاستيراد المؤجلة، أو لا شيء للفواتير خارج النطاق.

لكل صف خيار **اعتبار الضريبة أو الرسم لـ**:

| الخيار | الأثر |
| --- | --- |
| الإجمالي | يُضاف إلى إجمالي الفاتورة فقط (الضريبة) |
| التقييم | يُضاف إلى تكلفة المخزون دون المبلغ المستحق (نادر) |
| التقييم والإجمالي | يُضاف إلى كليهما، مثل شحن مفوتر في الفاتورة نفسها |

وخيار **إضافة أو خصم**، فيمكن للصف أن يزيد الإجمالي أو يخفضه.

:::warning الشحن في فاتورة البضائع
إذا فوتر المورد الشحن في الفاتورة نفسها، فأضفه كصف رسم مع **التقييم والإجمالي** ليصبح جزءاً من تكلفة المخزون، وإن جاء الشحن بفاتورة منفصلة فاستخدم [قسيمة التكاليف الواصلة](/stock/landed-cost).
:::

!fig جدول ضرائب المشتريات مع ضريبة المدخلات والشحن المضاف إلى التقييم

### الإجماليات والخصومات والتقريب

يمكن إدخال خصومات المورد لكل سطر أو كـ**خصم إضافي** على صافي الإجمالي، وحدد **تعطيل الإجمالي المقرّب** ليطابق المستحق فاتورة المورد تماماً.

### المدفوعات والدفعات المقدمة

| الحقل | وظيفته |
| --- | --- |
| جلب الدفعات المقدمة المدفوعة | يعرض الدفعات المقدمة للمورد لتطبيقها على هذه الفاتورة |
| مدفوعة مع طريقة الدفع والمبلغ | يسجّل الدفعة في الوقت نفسه |
| الشطب | يصفّي فرقاً متبقياً صغيراً |

### شروط الدفع

ينشئ **قالب شروط الدفع** الجدول الذي يعمل به فريق الذمم الدائنة، مثل 30% مقدماً و70% بعد 45 يوماً من الفاتورة.

### تفاصيل أخرى

- **عنوان المورد** و**جهة الاتصال**: يُطبعان في إشعارات الدفع.
- **رقم بيان الإدخال** (حقل مخصص): للواردات، يربط الفاتورة بالبيان الجمركي.
- **الملاحظات**: سبب الفاتورة، مثل "ديوا – مستودع القوز – مارس 2026".
- **المرفق**: أرفق دائماً ملف PDF أو صورة فاتورة المورد.

## سيناريوهات عملية

:::example فاتورة ديوا الشهرية
تستلم الواحة للتجارة فاتورة ديوا بقيمة 6,840 درهماً زائد ضريبة 342 درهماً لمستودع القوز، فينشئ المحاسب فاتورة مشتريات للمورد "هيئة كهرباء ومياه دبي"، ويضيف صنف المصروف *الكهرباء والمياه* بمركز تكلفة *مستودع القوز*، ويطبّق *ضريبة المدخلات 5%*، ويرفق الملف ويعتمد.
:::

:::example اشتراك برمجيات من الخارج
تُفوتر لؤلؤة لولو للأغذية بمبلغ 1,200 يورو من شركة برمجيات أيرلندية، فتكون الفاتورة باليورو بقالب **الاحتساب العكسي**، ويرحّل DocFlow ضريبة مخرجات ومدخلات 5% على القيمة بالدرهم، فيكون صافي تكلفة الضريبة صفراً ويصل المبلغان إلى الإقرار.
:::

:::example فوتر المورد سعراً خاطئاً
فوترت الخليج للحديد 2,950 درهماً للطن بدلاً من 2,880 المتفق عليها على 40 طناً. يُدخل المحاسب الفاتورة كما وردت ويطلب إشعاراً دائناً، ثم يسجّل إشعار المورد الدائن كـ[إشعار مدين](/accounting/credit-debit-notes) بمبلغ 2,800 درهم زائد الضريبة، أو يعلّق الفاتورة **معلّقة** حتى وصول الفاتورة المصححة.
:::

## مشكلات شائعة

:::details "رقم فاتورة المورد موجود في فاتورة مشتريات"
أُدخل رقم المورد نفسه سابقاً لهذا المورد، فتحقق من أن الفاتورة ليست مكررة قبل التجاوز.
:::

:::details "إيصال الاستلام مطلوب للصنف"
تشترط إعدادات المشتريات إيصالاً، فاستلم البضاعة أولاً أو اطلب من المسؤول تخفيف الإعداد لأصناف الخدمات.
:::

:::details ضريبة المدخلات لا تظهر في الإقرار
الفاتورة دون قالب ضريبي، أو حساب القالب ليس حساب ضريبة، أو تاريخ الترحيل خارج فترة الإقرار.
:::

:::details إجمالي الفاتورة يختلف عن فاتورة المورد ببضعة فلوس
حدد **تعطيل الإجمالي المقرّب**، أو عدّل بحقل الشطب عند الدفع.
:::

:::details لا يمكن الإلغاء لارتباط قيد دفع
ألغِ الدفعة أولاً، أو حدد **فك ربط الدفعة عند إلغاء الفاتورة** في إعدادات الحسابات لتصبح الدفعة دفعة مقدمة.
:::

## أنواع الدفع

| نوع الدفع | يُستخدم لـ | الطرف |
| --- | --- | --- |
| استلام | الأموال الواردة من العملاء (أو المبالغ المستردة من الموردين) | عميل، مورد، موظف، مساهم |
| دفع | الأموال الصادرة للموردين (أو المبالغ المعادة للعملاء) | مورد، عميل، موظف، مساهم |
| تحويل داخلي | نقل الأموال بين حساباتك | لا يوجد |

## طرق إنشاء الدفعة

1. **من فاتورة**: انقر **إنشاء › دفعة**، فيُملأ الطرف والمبلغ والمرجع.
2. **من أمر بيع أو شراء**: يسجّل دفعة مقدمة مقابل الأمر.
3. **قيد دفع جديد**: للمقبوضات التي تغطي عدة فواتير أو الدفعات المقدمة دون أمر.
4. **من طلب دفع**: تنشئ المدفوعات الإلكترونية بالبطاقة قيوداً تلقائياً ([الدليل](/accounting/payment-request)).
5. **من التسوية البنكية**: أنشئ القيد أثناء مطابقة سطر الكشف ([الدليل](/accounting/bank-reconciliation)).

### التخصيص للفواتير

يعرض جدول **مراجع الدفع** الفواتير أو الأوامر التي تسددها الدفعة.

1. انقر **جلب الفواتير المستحقة** (أو **جلب الأوامر المستحقة**).
2. صفِّ حسب نطاق التاريخ أو تاريخ الاستحقاق أو المبلغ عند الحاجة.
3. حدد المستندات وعيّن **المبلغ المخصص** لكل منها.
4. يبقى أي مبلغ غير مخصص **مبلغاً غير مخصص** ويُعامل كدفعة مقدمة.

## الدفعات المقدمة

الأموال المستلمة أو المدفوعة قبل وجود فاتورة **دفعة مقدمة**.

- اترك جدول المراجع فارغاً، أو اربط الدفعة بأمر البيع أو الشراء.
- عند إنشاء الفاتورة استخدم **جلب الدفعات المقدمة** فيها، أو [مطابقة المدفوعات](/accounting/payment-reconciliation) بعدها.
- يمكنك ترحيل الدفعات المقدمة إلى حسابي **دفعات مقدمة مستلمة** و**دفعات مقدمة مدفوعة** منفصلين بدلاً من حسابي المدينين والدائنين، بتعيينهما في الشركة، فتبقى ظاهرة في الميزانية العمومية.

:::uae الضريبة على دفعات العملاء المقدمة
تستحق الضريبة على الدفعات المقدمة من العملاء عند وصول المال، فحدد **تطبيق الضريبة على الدفعة المقدمة** واختر قالب الضريبة لتُرحَّل ضريبة المخرجات مع المقبوض. راجع [تاريخ التوريد](/uae-compliance/tax-point).
:::

## الشيكات

### استلام شيك حالي

سجّل قيد **استلام** إلى حسابك البنكي برقم الشيك وتاريخه، وأودع الشيك، وصفِّه في التسوية البنكية عند ظهوره في الكشف.

### الشيكات المؤجلة

1. سجّل المقبوض إلى حساب **شيكات مؤجلة مستلمة** (نوع الحساب مدينون أو حساب مخصص للشيكات المؤجلة) مع تاريخ الشيك تاريخاً مرجعياً.
2. في تاريخ الشيك أو بعده، انقله إلى البنك بقيد دفع من نوع **تحويل داخلي** من الشيكات المؤجلة المستلمة إلى الحساب البنكي.
3. تعمل شيكات الموردين المؤجلة بالطريقة نفسها مع حساب **شيكات مؤجلة مدفوعة**.

يعرض **سجل الشيكات المؤجلة**، وهو تقرير محفوظ للمدفوعات على حسابات الشيكات المؤجلة مرتب حسب التاريخ المرجعي، الشيكات المستحقة هذا الأسبوع.

### الشيكات المرتجعة

ألغِ قيد الدفع (أو رحّل قيداً عكسياً إن كانت الفترة مقفلة)، فتعود الفاتورة مستحقة، وسجّل رسوم الارتجاع البنكية كمصروف، وأعد تحميلها على العميل إن سمحت شروطك.

### الشيكات القديمة غير المقدمة

يمكن إعادة قيد الشيك الذي لم يُقدّم أبداً، فرحّل قيداً من الشيكات المؤجلة المدفوعة (أو البنك) إلى الدائن، ثم أعد إصدار الدفعة عند الحاجة.

!fig سجل الشيكات المؤجلة مرتباً حسب تاريخ الاستحقاق

## التحويلات الداخلية

استخدم **التحويل الداخلي** لنقل الأموال بين حساباتك: من البنك إلى النثرية، ومن حساب الدرهم إلى حساب الدولار، ومن الحساب الجاري إلى الوديعة. أدخل المبلغين إن اختلفت العملتان، فيسجّل DocFlow فرق الصرف.

## الدفع لموردين كثيرين دفعة واحدة

أنشئ **أمر دفع** من طلبات الدفع المعتمدة أو فواتير المشتريات، فيجمع المدفوعات حسب البنك لترفع ملفاً جماعياً واحداً إلى الخدمات المصرفية الإلكترونية، ويُنشئ كل سطر قيد الدفع الخاص بمورده. راجع [المدفوعات الجماعية للموردين](/accounting/payment-order).

## الإيصالات وإشعارات الدفع

- اطبع **إيصالاً** للعملاء الذين يدفعون نقداً أو بشيك على ترويستك.
- أرسل **إشعار دفع** بالبريد للموردين يبيّن الفواتير المدفوعة ليطابقوا بسرعة.

## إنشاء قيد يومية

1. انتقل إلى **المحاسبة › قيد اليومية › جديد**.
2. اختر **نوع القيد** و**تاريخ الترحيل**.
3. أضف صفاً لكل حساب بمبلغه **المدين** أو **الدائن**، واختر **نوع الطرف** و**الطرف** للمدينين والدائنين، وعيّن **مركز التكلفة** والأبعاد الأخرى عند الحاجة، واستخدم **نوع المرجع** و**اسم المرجع** لربط صف بفاتورة فيسددها.
4. تحقق من تساوي إجمالي المدين والدائن، ويظهر الفرق في الأسفل.
5. اكتب **ملاحظة المستخدم** بوضوح.
6. أرفق المستندات الداعمة.
7. احفظ واعتمد.

## القوالب والقيود المتكررة

- احفظ **قالب قيد يومية** للقيود المتكررة بحساباتها وأطرافها، واختر القالب في قيد جديد وأدخل المبالغ فقط.
- استخدم [التكرار التلقائي](/framework/automation) للقيود الشهرية الثابتة كإطفاء الإيجار.

## عكس القيد

للمستحقات التي يجب إلغاؤها عند وصول الفاتورة الفعلية، افتح القيد وانقر **إنشاء › قيد يومية عكسي** بتاريخ أول الشهر التالي، فيبدّل القيد الجديد المدين والدائن ويسجّل **عكس لـ**.

## القيود متعددة العملات

حدد **متعدد العملات** للترحيل إلى حسابات بعملات مختلفة، مثل الدفع لمورد بالدولار من حساب بالدرهم، فيعرض كل صف عملة الحساب وسعر الصرف والمبالغ بالعملتين.

## ما يحدث خلف الكواليس

يرحّل القيد الصفوف التي تدخلها تماماً إلى دفتر الأستاذ العام، وتظهر الصفوف التي تستخدم المدينين أو الدائنين مع طرف في دفتر ذلك الطرف وتقارير الذمم، وتغيّر الصفوف المرتبطة بفاتورة المبلغ المستحق عليها.

## مشكلات شائعة

:::details "يجب أن يساوي إجمالي المدين إجمالي الدائن"
الصفوف غير متوازنة، فأضف صفاً أو صحّح مبلغاً، ويظهر الفرق في الأسفل.
:::

:::details "نوع الطرف والطرف مطلوبان لحساب المدينين / الدائنين"
تحتاج الصفوف على حسابات المدينين أو الدائنين إلى طرف.
:::

:::details "الحساب مجمّد" أو "لا يُسمح بالترحيل في فترة مقفلة"
الحساب أو الفترة مقفلة، فاطلب من مدير الحسابات.
:::

:::details لم يخفض القيد المبلغ المستحق على الفاتورة
لا يحمل الصف **نوع المرجع** و**اسم المرجع**، فاربطه بالفاتورة أو استخدم [مطابقة المدفوعات](/accounting/payment-reconciliation).
:::

:::details هل أستخدم قيد يومية للضريبة؟
تجنب ذلك، فالقيود المرحّلة إلى حسابات الضريبة لا تحمل الإمارة والمبلغ الخاضع وبيانات الفاتورة التي يحتاجها تقرير VAT 201، فاستخدم الفواتير والإشعارات الدائنة والمدينة.
:::

@summary صحّح الفواتير بطريقة متوافقة مع الضريبة: المرتجعات وتخفيضات الأسعار والحسومات والرسوم الإضافية وطريقة تخصيصها.

| الحالة | المستند | من يصدره |

## الإشعارات الدائنة للمبيعات

1. افتح فاتورة المبيعات الأصلية.
2. انقر **إنشاء › مرتجع / إشعار دائن**.
3. يحمل المستند الجديد **مرتجع** محدداً و**مرتجع مقابل** معيّناً إلى الأصل.
4. عدّل الكميات (سالبة) أو الأسعار لما يُضاف لحساب العميل، واحذف الأسطر غير المتأثرة.
5. حدد **تحديث المخزون** إن كانت البضاعة تعود فعلياً وكانت الفاتورة الأصلية قد حدّثت المخزون، وإن جاءت عبر إذن تسليم فأنشئ [مرتجع مبيعات](/selling/sales-returns) من الإذن بدلاً من ذلك.
6. أدخل السبب في **الملاحظات**، مثل "إرجاع وحدتين – تضررتا أثناء النقل".
7. اعتمد وأرسل الإشعار الدائن إلى العميل.

!fig إشعار دائن مُنشأ من فاتورة مبيعات بكميات سالبة وسبب

### تخفيض السعر دون إرجاع بضاعة

أبقِ الكمية الأصلية وعيّن السعر بمقدار التخفيض، أو استخدم سطر خدمة واحداً مثل "تسوية سعر" بمبلغ الإشعار، ولا تحدد تحديث المخزون.

### حسومات الكميات على فواتير كثيرة

لحسم نهاية السنة الذي يغطي فواتير كثيرة، أنشئ إشعاراً دائناً واحداً بصنف حسم، واترك **مرتجع مقابل** فارغاً إن لم يتعلق بفاتورة واحدة، واشرح طريقة الاحتساب في الملاحظات. راجع مستشارك الضريبي بشأن تعديل الضريبة، فذلك يعتمد على هيكلة الحسم.

## الإشعارات المدينة للمبيعات

1. افتح فاتورة المبيعات الأصلية وانقر **إنشاء › إشعار مدين** (أو أنشئ فاتورة جديدة مع تحديد **إشعار مدين** وتعيين **مرتجع مقابل**).
2. أضف المبلغ الإضافي، مثل شحن فائت أو زيادة سعر متفق عليها بعد التسليم.
3. اعتمد، فيصبح العميل مديناً بالمبلغ الإضافي زائد الضريبة.

## الإشعارات المدينة للمشتريات

1. افتح فاتورة المشتريات الأصلية.
2. انقر **إنشاء › مرتجع / إشعار مدين**.
3. أدخل الكميات أو المبالغ المخفضة.
4. أدخل رقم إشعار المورد الدائن في **رقم فاتورة المورد** إن كان قد أصدره.
5. اعتمد، فتنخفض ذمتك الدائنة وضريبة المدخلات.

إذا أُعيدت البضاعة فعلياً، فأنشئ [مرتجع مشتريات](/buying/purchase-returns) من الإيصال أولاً.

## كيف تُسوّى الإشعارات الدائنة والمدينة

- يخفض الإشعار الدائن المرتبط بفاتورة محددة المبلغ المستحق عليها تلقائياً.
- إن كانت الفاتورة مسددة، يبقى الإشعار رصيداً دائناً في حساب العميل، فأعده بقيد دفع (**دفع** للعميل) أو قاصّه بفاتورة لاحقة عبر [مطابقة المدفوعات](/accounting/payment-reconciliation).

:::uae الإشعارات الدائنة الضريبية
يجب أن يحمل الإشعار الدائن الضريبي في الإمارات عبارة "إشعار دائن ضريبي"، واسمك وعنوانك ورقمك الضريبي، وبيانات العميل، والتاريخ، والإشارة إلى الفاتورة الضريبية الأصلية، وقيمة التعديل والضريبة المخفضة، وسبباً موجزاً. استخدم تنسيق **الإشعار الدائن الضريبي الإماراتي**، ويُبلَّغ تخفيض الضريبة في فترة إصدار الإشعار.
:::

## ما يحدث خلف الكواليس

إشعار دائن للمبيعات بقيمة 2,000 درهم زائد الضريبة:

| الحساب | مدين | دائن |
| --- | --- | --- |
| مرتجعات المبيعات (أو مبيعات البضائع) | 2,000 | |
| ضريبة المخرجات 5% | 100 | |
| المدينون – العميل | | 2,100 |

إذا عاد مخزون تكلفته 1,200 درهم، يجعل قيد ثانٍ المخزون المتوفر مديناً وتكلفة البضاعة المباعة دائنة.

إشعار مدين للمشتريات بقيمة 2,800 درهم زائد الضريبة:

| الحساب | مدين | دائن |
| --- | --- | --- |
| الدائنون – المورد | 2,940 | |
| بضاعة مستلمة غير مفوترة (أو المصروف) | | 2,800 |
| ضريبة المدخلات 5% | | 140 |

## إعداد الحسابات البنكية

1. أنشئ سجل **بنك** لكل بنك تتعامل معه، مثل الإمارات دبي الوطني وبنك أبوظبي الأول وبنك أبوظبي التجاري والمشرق وبنك رأس الخيمة الوطني ومصرف أبوظبي الإسلامي.
2. أنشئ **حساباً بنكياً** لكل حساب: اربطه بالبنك والشركة وحساب الأستاذ وأدخل رقم IBAN.
3. حدد **حساب شركة**.

## استيراد الكشف

1. انتقل إلى **المحاسبة › أداة التسوية البنكية**.
2. اختر الشركة والحساب البنكي، وعيّن **من تاريخ** و**إلى تاريخ**.
3. أدخل الرصيدين الافتتاحي والختامي للكشف.
4. انقر **رفع كشف الحساب** وأرفق الملف، واربط الأعمدة في المرة الأولى: التاريخ والوصف والإيداع والسحب والمرجع والرصيد.
5. انقر **اعتماد**، فيصبح كل سطر **معاملة بنكية**.

## مراكز التكلفة

مراكز التكلفة شجرة مثل دليل الحسابات، ولكل شركة مركز رئيسي تتفرع منه المراكز.

| هيكل مثال | الاستخدام |
| --- | --- |
| الواحة للتجارة › دبي › صالة العرض، المستودع | ربح الفرع والموقع |
| الواحة للتجارة › معدات المطابخ، قطع الغيار، الخدمة | ربح القطاع |
| صقر للحديد › الإنتاج › القص، اللحام، الطلاء | تتبع تكاليف الإنتاج |

### إنشاء مراكز التكلفة

1. انتقل إلى **المحاسبة › شجرة مراكز التكلفة**.
2. اختر الأم وانقر **إضافة فرعي**.
3. حدد **مجموعة** للعناوين، واتركه دون تحديد للمراكز التي تستقبل القيود.

### تعيين الإعدادات الافتراضية

يختار DocFlow مركز التكلفة بهذا الترتيب: سطر المستند، ثم الإعداد الافتراضي للصنف أو مجموعته، ثم العميل أو المورد، ثم المشروع، ثم الشركة. عيّن الإعدادات الافتراضية حيث تفيد حتى نادراً ما يحتاج الموظفون إلى الاختيار.

!fig شجرة مراكز التكلفة مع فرعي دبي وأبوظبي والقطاعات

## الأبعاد المحاسبية

عندما لا يكفي عرض إضافي واحد، أضف **أبعاداً محاسبية**، مثل الفرع *و*المشروع *و*المندوب.

1. انتقل إلى **المحاسبة › البُعد المحاسبي › جديد**.
2. اختر **المستند المرجعي**، مثل الفرع أو المشروع أو قائمة مخصصة كـ"خط الأعمال".
3. عيّن الإعدادات الافتراضية لكل شركة، وحدد **إلزامي للميزانية العمومية** أو **إلزامي للأرباح والخسائر** إن وجب أن يحمله كل قيد.
4. احفظ، فيظهر البُعد في كل معاملة وكعامل تصفية في كل تقرير مالي.

استخدم **تصفية الأبعاد المحاسبية** لتقييد القيم المسموح بها مع حسابات معينة، مثل السماح ببُعد المشروع فقط على حسابات تكاليف المشاريع.

## توزيع التكاليف العامة

تخدم تكاليف المكتب الرئيسي، كالإيجار وتقنية المعلومات والمالية ورواتب الإدارة، كل الفروع، و**توزيع مركز التكلفة** يقسمها تلقائياً.

1. انتقل إلى **المحاسبة › توزيع مركز التكلفة › جديد**.
2. اختر **المركز الرئيسي**، مثل *المكتب الرئيسي*.
3. أضف المراكز المستهدفة بنسبها، مثل دبي 50% وأبوظبي 30% والشارقة 20%.
4. عيّن تاريخ **ساري من** واعتمد.

يُقسَّم كل قيد يُرحَّل إلى المكتب الرئيسي من ذلك التاريخ تلقائياً في التقارير.

## الموازنات

### إنشاء موازنة

1. انتقل إلى **المحاسبة › الموازنة › جديد**.
2. اختر **الموازنة مقابل**: مركز التكلفة أو المشروع أو بُعد آخر.
3. اختر مركز التكلفة أو المشروع و**السنة المالية**.
4. اختر **توزيعاً شهرياً** اختيارياً لتوزيع المبلغ السنوي بشكل غير متساوٍ.
5. أضف حسابات المصروفات والمبالغ السنوية.
6. عيّن الضوابط:

| الضابط | الإجراء عند التجاوز |
| --- | --- |
| الموازنة السنوية على طلب المواد | إيقاف أو تحذير أو تجاهل |
| الموازنة السنوية على أمر الشراء | إيقاف أو تحذير أو تجاهل |
| الموازنة السنوية على المصروفات الفعلية | إيقاف أو تحذير أو تجاهل |
| الموازنة الشهرية (لكل مما سبق) | إيقاف أو تحذير أو تجاهل |

7. اعتمد.

!fig موازنة مركز تكلفة التسويق مع توزيع شهري وضوابط تحذير

### التوزيع الشهري

يحدد **التوزيع الشهري** حصة الموازنة السنوية لكل شهر، فقد يضع متجر تجزئة مثلاً 14% في ديسمبر و6% في يوليو، وتستخدم ضوابط الموازنة الشهرية وتقارير الانحراف هذه الحصص.

### مراجعة الموازنة

الموازنات مستندات معتمدة، فلتغييرها ألغِ وعدّل، أو أنشئ سجل **مراجعة موازنة** يوثّق السبب والمعتمد.

### انحراف الموازنة

يقارن **تقرير انحراف الموازنة** الموازنة بالفعلي حسب الحساب والشهر مع الانحراف ونسبته، فاستخدمه في اجتماعات الإدارة الشهرية.

:::example مثال: موازنة التسويق لمعرض
تضع الواحة للتجارة موازنة تسويق بقيمة 120,000 درهم لعام 2026 مرجحة نحو أكتوبر لمعرض تجاري في دبي. عندما يرفع حجز الجناح إنفاق سبتمبر فوق الموازنة الشهرية، يرى موظف المشتريات تحذيراً في أمر الشراء ويُبلَّغ المدير المالي، ولأن الموازنة السنوية ما زالت ضمن الحد يمضي الطلب.
:::

## تقارير بمراكز التكلفة والأبعاد

- **الأرباح والخسائر** و**الميزانية العمومية**: صفِّ حسب مركز التكلفة أو أي بُعد.
- **تحليل الربحية**: الإيرادات والمصروفات والربح حسب مركز التكلفة أو المشروع في عرض واحد.
- **دفتر الأستاذ العام**: جمّع حسب مركز التكلفة لرؤية كل قيد.

## مشكلات شائعة

:::details "تم تجاوز الموازنة السنوية للحساب"
الضابط معيّن على الإيقاف، ويمكن لمستخدم بالدور المناسب مراجعة الموازنة أو تغيير الضابط إلى تحذير.
:::

:::details "البُعد المحاسبي إلزامي"
البُعد محدد إلزامياً لهذا النوع من التقارير، فاملأه في المعاملة أو عيّن قيمة افتراضية للشركة.
:::

:::details قيود قديمة دون مركز تكلفة
صفِّ دفتر الأستاذ العام للمراكز الفارغة وصحّحها بقيود يومية قبل إقفال السنة.
:::

## الإعداد

### أسعار الصرف

- **يدوياً**: أضف الأسعار في **المحاسبة › صرف العملات**، مثل الدولار إلى الدرهم = 3.6725 من 1 يناير 2026.
- **تلقائياً**: في **إعدادات صرف العملات** اختر مزود أسعار، فيجلب DocFlow السعر اليومي عند الحاجة.
- **الأسعار القديمة**: في [إعدادات الحسابات](/accounting/accounts-settings) اختر ما إذا كان يُسمح بآخر سعر متاح عند غياب سعر اليوم.

:::uae ربط الدرهم
الدرهم مربوط بالدولار عند 3.6725، فأضف سعراً ثابتاً للدولار بصلاحية طويلة، فلا تنشأ عن فواتير الدولار فروقات صرف بسبب تغير السعر، بل فقط من الرسوم البنكية أو التقريب. ويجب إظهار مبالغ الضريبة في فواتير العملات الأجنبية بالدرهم بسعر مصرف الإمارات العربية المتحدة المركزي.
:::

### حسابات الأطراف بالعملات الأجنبية

لديك خياران:

| الطريقة | الإعداد | الأنسب لـ |
| --- | --- | --- |
| حساب مدينين بالدرهم | يُفوتر العميل بالدولار والدفتر بالدرهم | معاملات أجنبية قليلة |
| حساب مدينين بالدولار | أنشئ *المدينون – دولار* بعملة الدولار وعيّنه على العميل | العملاء الأجانب المنتظمون، فتُتتبع الأرصدة بالدولار |

تثبت عملة حساب الطرف بعد أول معاملة، ولتغييرها أنشئ سجل عميل أو حساباً منفصلاً.

### الحسابات البنكية بالعملات الأجنبية

أنشئ حساب أستاذ بـ**عملة الحساب** دولار (أو يورو) تحت الحسابات البنكية، مرتبطاً بسجل **حسابه البنكي**، فتُسجَّل المدفوعات منه وإليه بالدولار.

## المعاملات

- **مستندات المبيعات والمشتريات**: اختر العملة، فيُملأ سعر الصرف من تاريخ الترحيل، وتظهر المبالغ بالعملتين في النموذج.
- **قيود الدفع**: أدخل المبلغ المدفوع والمستلم بعملة كل حساب، فيحتسب DocFlow الفرق مقابل سعر الفاتورة.
- **قيود اليومية**: حدد **متعدد العملات** وأدخل سعر الصرف لكل صف.

!fig فاتورة مبيعات بالدولار تعرض سعر الصرف وما يعادله بالدرهم

## فروقات الصرف المحققة

عندما تُسدَّد فاتورة باليورو مسجلة بسعر 4.05 بسعر 4.10، تكون القيمة المستلمة بالدرهم أعلى من قيمة الفاتورة بالدرهم، فانقر **تعيين أرباح/خسائر الصرف** في قيد الدفع فيرحّل DocFlow الفرق إلى **أرباح/خسائر الصرف**.

## فروقات الصرف غير المحققة: إعادة التقييم

في نهاية الشهر أعد تقييم الأرصدة المفتوحة بالعملات الأجنبية.

1. انتقل إلى **المحاسبة › إعادة تقييم سعر الصرف › جديد**.
2. اختر الشركة وتاريخ إعادة التقييم.
3. انقر **جلب القيود**، فيعرض DocFlow حسابات المدينين والدائنين والبنوك بالعملات الأجنبية بأرصدتها والسعر الحالي والقيمة الجديدة بالدرهم.
4. راجع واعتمد، ثم انقر **إنشاء قيد يومية**.

يرحّل القيد الربح أو الخسارة غير المحققة، وتعكسه شركات كثيرة في أول يوم من الشهر التالي فلا يبقى إلا الفروقات المحققة.

## عملة العرض

لعرض القوائم المالية بعملة أخرى، كالدولار لشركة أم أجنبية، اختر **عملة العرض** في التقرير، فيحوّل DocFlow الأرقام بالسعر المحدد دون تغيير الدفاتر.

| --- | --- | --- |

## قفل الفترة

لديك أداتان:

| الأداة | وظيفتها | متى تستخدمها |
| --- | --- | --- |
| **تجميد الحسابات حتى تاريخ** (إعدادات الحسابات) | يمنع كل الترحيلات في التاريخ أو قبله إلا لدور محدد | القفل الشهري البسيط |

## إقفال نهاية السنة

### قبل قسيمة إقفال الفترة

1. أكمل إقفال شهر ديسمبر.
2. اجرد المخزون ورحّل [تسوية المخزون](/stock/stock-reconciliation).
3. تحقق من الأصول الثابتة ورحّل الإهلاك حتى نهاية السنة.
4. حدّث المخصصات: المكافأة وتذاكر السفر والإجازات والديون المشكوك فيها.
5. أكّد الأرصدة مع كبار العملاء والموردين.
6. رحّل استحقاق ضريبة الشركات للسنة.
7. اتفق على تسويات التدقيق مع مدققك.

### قسيمة إقفال الفترة

تنقل **قسيمة إقفال الفترة** صافي ربح السنة أو خسارتها من كل حسابات الإيرادات والمصروفات إلى حساب حقوق ملكية، فتبدأ السنة التالية بإيرادات ومصروفات صفرية.

1. انتقل إلى **المحاسبة › قسيمة إقفال الفترة › جديد**.
2. اختر **الشركة** و**تاريخ المعاملة** (عادةً آخر يوم في السنة) و**السنة المالية**.
3. اختر **حساب الإقفال**، وعادةً *الأرباح المحتجزة*.
4. أضف ملاحظة واعتمد.

يحتسب DocFlow الأرصدة في الخلفية ويرحّل قيود الإقفال لكل حساب إيرادات ومصروفات.

!fig قسيمة إقفال الفترة للسنة المالية 2026

### بعد القسيمة

- إذا اقترح المدقق تسويات لاحقاً، رحّلها بتاريخ 31 ديسمبر ثم ألغِ قسيمة الإقفال وأعد اعتمادها.
- قدّم تاريخ التجميد إلى 31 ديسمبر بعد توقيع التدقيق.
- حوّل الاحتياطي القانوني إن كانت شركتك تكوّنه.

:::uae ضريبة الشركات والسنة المقفلة
يعتمد إقرار ضريبة الشركات على الحسابات المدققة للفترة الضريبية، فاحفظ ميزان مراجعة السنة المقفلة والأرباح والخسائر وتعديلاتك الضريبية معاً. راجع [ضريبة الشركات](/uae-compliance/corporate-tax).
:::

## تخصيص القوائم

- تتيح **قوالب التقارير المالية** تعريف تخطيطك الخاص: الحسابات التي تذهب إلى كل سطر والمجاميع الفرعية والعناوين، فاستخدمها لتقارير الالتزامات البنكية أو تنسيق الإدارة.
- تجمّع **فئات الحسابات** الحسابات في أسطر قياسية كـ"الذمم التجارية المدينة" أو "النقد وما يعادله"، وهي مفيدة لاتساق إيضاحات الحسابات.
- يوزّع **ربط التدفقات النقدية** الحسابات على الأنشطة التشغيلية والاستثمارية والتمويلية إن لم يناسبك التصنيف الافتراضي.

## مشاركة التقارير

- **الطباعة أو PDF**: بترويستك من قائمة التقرير.
- **التصدير**: إلى Excel أو CSV لمزيد من العمل.
- **تقرير البريد التلقائي**: إرسال تقرير محفوظ وفق جدول، مثل ملخص الذمم المدينة كل اثنين ([الدليل](/framework/report-builder)).
- **التقارير المُعدّة مسبقاً**: تعمل التقارير الكبيرة في الخلفية وتُحفظ للعرض السريع.

:::uae تقارير للبنوك والجهات
تطلب البنوك الإماراتية عادةً القوائم السنوية المدققة مع حسابات إدارية حديثة، وتبدأ أوراق عمل ضريبة الشركات من الأرباح والخسائر للفترة الضريبية كاملة، فاحفظ نسخة من كل تقرير نهاية سنة مع ملف الإقفال.
:::

## تسويات البطاقات

تذهب مبيعات البطاقات أولاً إلى حساب تسوية، وعندما يسوّي المحصّل، عادةً بعد يوم أو يومين بعد خصم رسومه:

| الخطوة | مدين | دائن |
| --- | --- | --- |
| البيع | تسوية البطاقات 1,050 | المبيعات 1,000 وضريبة المخرجات 50 |
| التسوية | البنك 1,029 ورسوم البطاقات 21 | تسوية البطاقات 1,050 |

طابق حساب التسوية أسبوعياً، ويجب أن يكون قريباً من الصفر عدا مبيعات آخر يوم أو يومين.

:::

## أين تُطبَّق الشروط

يختار DocFlow القالب بهذا الترتيب: المستند، ثم العميل أو المورد، ثم مجموعته، ثم الإعداد الافتراضي للشركة، ويبني القالب **جدول دفعات** في الأمر والفاتورة، صفاً لكل شرط بتاريخ استحقاقه ومبلغه.

## خصومات السداد المبكر

عند إنشاء قيد دفع خلال صلاحية الخصم، يقترح DocFlow الخصم ويرحّله إلى حساب **الخصم المسموح به** (المبيعات) أو **الخصم المكتسب** (المشتريات) كخصم.

:::uae الخصومات والضريبة
خصم السداد المبكر بعد إصدار الفاتورة الضريبية يخفض المقابل، فإن كان المبلغ كبيراً فأصدر إشعاراً دائناً ضريبياً لتُعدَّل الضريبة بشكل صحيح.
:::

## تتبع الأقساط

يعرض تقرير **حالة شروط الدفع لأمر البيع** كل قسط وما إذا كان قد فُوتر وسُدد وما هو متأخر، فاستخدمه للمشاريع والطلبات الكبيرة.

:::uae المحتجزات في المقاولات
كثيراً ما تحتجز أعمال التشطيب والمقاولات 5–10% حتى انتهاء فترة ضمان العيوب، والشرط المنفصل للمحتجزات يبقيها خارج أرقام التأخير العادية ويسهّل متابعتها عند استحقاقها.
:::

## مشكلات شائعة

:::details "يجب أن يساوي إجمالي جدول الدفعات الإجمالي الكلي"
القالب لا يساوي 100%، أو تغيّرت الفاتورة بعد بناء الجدول، فأعد اختيار القالب.
:::

:::details تاريخ الاستحقاق ليس كما توقعت

:::

@@ payment-reconciliation | مطابقة المدفوعات
@summary طابق الدفعات غير المخصصة والدفعات المقدمة والإشعارات الدائنة والقيود مع الفواتير المفتوحة، وتراجع عن التخصيصات عند الحاجة.

مع الوقت قد يتجمع في حساب العميل أو المورد مدفوعات غير مرتبطة بأي فاتورة: دفعات مقدمة ومبالغ مجمعة وإشعارات دائنة وتسويات قيود، وحتى تُطابق تبدو الفواتير غير مسددة وتكون تقارير الأعمار خاطئة، و**مطابقة المدفوعات** تربط بينها.

## متى تستخدمها

- دفع العميل عدة فواتير بتحويل واحد دون تحديدها.
- استُلمت دفعة مقدمة قبل وجود الفاتورة.
- صدر إشعار دائن دون ربطه بفاتورته.
- سوّى قيد يومية رصيداً دون الإشارة إلى الفاتورة.

## تشغيل المطابقة

1. انتقل إلى **المحاسبة › مطابقة المدفوعات**.
2. اختر **الشركة** و**نوع الطرف** (عميل أو مورد) و**الطرف**.
3. اختر **حساب المدينين / الدائنين**.
4. صفِّ اختيارياً حسب نطاق التواريخ أو الحد الأدنى والأقصى للمبلغ أو مركز التكلفة.
5. انقر **جلب القيود غير المطابقة**، فيظهر جدولان: **الفواتير** (الفواتير والإشعارات المدينة المفتوحة) و**المدفوعات** (المدفوعات غير المخصصة والدفعات المقدمة والإشعارات الدائنة والقيود).
6. حدد الفواتير والمدفوعات المراد مطابقتها وانقر **تخصيص**، فيطابق DocFlow الأقدم أولاً، وعدّل المبالغ المخصصة عند الحاجة.
7. راجع جدول **التخصيص** بما في ذلك أي فرق صرف.
8. انقر **مطابقة**.

!fig مطابقة مدفوعات تربط دفعتين بثلاث فواتير

## مطابقة أطراف كثيرة

تشغّل **معالجة مطابقة المدفوعات** المطابقة نفسها لكل الأطراف (أو مجموعة مصفّاة) في الخلفية، مثل كل نهاية شهر، فراجع سجلها للأطراف التي لم تُطابق تلقائياً.

## التراجع عن المطابقة

إذا طوبقت دفعة مع الفاتورة الخطأ، افتح الدفعة واستخدم **إلغاء المطابقة**، أو أداة **إلغاء مطابقة الدفعة** واختر التخصيصات المراد إزالتها، فتعود الدفعة غير مخصصة ويمكن مطابقتها بشكل صحيح.

## فروقات الصرف

عند مطابقة دفعة بعملة أجنبية مع فاتورة بسعر مختلف، يعرض التخصيص الفرق، ويرحّله DocFlow إلى أرباح/خسائر الصرف عند المطابقة.

## مشكلات شائعة

:::details لم يُعثر على قيود
تحقق من حساب المدينين أو الدائنين والتواريخ، فالمدفوعات المرحّلة إلى حساب دفعات مقدمة منفصل لا تظهر إلا عند اختياره.
:::

:::details التخصيص أكبر من المبلغ المستحق
خفّض مستند آخر الفاتورة بالفعل، فحدّث القيود.
:::

@@ payment-request | طلبات الدفع وروابط الدفع
@summary أرسل للعملاء رابطاً للدفع الإلكتروني، واطلب اعتماد الدفعات داخلياً، وسجّل المدفوعات الإلكترونية تلقائياً.

3. أنشئ **حساب بوابة دفع** يربط البوابة بحساب تسوية وعملة.
4. عيّن اختيارياً رسالة بريد افتراضية لطلبات الدفع.

## طلب الدفع من عميل

1. افتح أمر بيع أو فاتورة مبيعات معتمدة.
2. انقر **إنشاء › طلب دفع**.
3. تحقق من حساب البوابة والمبلغ (كاملاً أو جزئياً، كدفعة مقدمة 30%) ورسالة البريد.
4. انقر **إرسال**، فيتلقى العميل رسالة برابط **ادفع الآن**.
5. عند دفع العميل تؤكد البوابة، فيصبح الطلب **مدفوعاً** ويُنشأ قيد دفع تلقائياً مقابل حساب التسوية.

!fig رسالة طلب دفع برابط ادفع الآن

## طلبات الدفع الداخلية

لمدفوعات الموردين التي تحتاج إلى اعتماد، أنشئ طلب دفع من فاتورة المشتريات بـ**نوع طلب الدفع = صادر**، فتعتمده المالية عبر [سير عمل](/framework/workflows) ثم تدفع أو تضيفه إلى **أمر دفع** للبنك.

## الحالات

| الحالة | المعنى |
| --- | --- |
| مسودة / مطلوب | أُنشئ وأُرسل |
| بدأ الدفع | بدأ العميل الدفع |
| مدفوع | استُلمت الدفعة |
| مدفوع جزئياً | استُلم جزء |
| فشل / ملغى | لم يكتمل |

:::

@summary تابع الفواتير المتأخرة بتذكيرات متصاعدة ورسوم اختيارية وروتين تحصيل واضح.

**المطالبات** طريقة منظمة لتذكير العملاء بالفواتير المتأخرة، فكل مستند مطالبة يعرض المبالغ المتأخرة ويطبّق الرسوم أو الفوائد المتفق عليها ويُرسل برسالة تناسب مدة التأخير.

:::note قبل أن تبدأ
- يجب أن تحمل الفواتير تواريخ استحقاق صحيحة من [شروط الدفع](/accounting/payment-terms).
- يحتاج كل عميل إلى جهة اتصال رئيسية ببريد للحسابات.
- اتفق مع الإدارة على النبرة المستخدمة في كل مرحلة وما إذا كنت تفرض رسوم تأخير.
:::

## أنواع المطالبات

**نوع المطالبة** مستوى واحد من التذكير.

| الحقل | وظيفته |
| --- | --- |
| اسم نوع المطالبة | مثل "التذكير الأول" و"التذكير الثاني" و"الإنذار النهائي" |
| رسوم المطالبة | رسم ثابت يُضاف إلى المطالبة |
| نسبة الفائدة (% سنوياً) | فائدة تُحتسب على أيام التأخير |
| حساب الإيرادات | حيث تُرحَّل الرسوم والفوائد |
| مركز التكلفة | للتقارير |
| نص خطاب المطالبة | النص والخاتمة لكل لغة |

أنشئ نص الخطاب بالعربية والإنجليزية في كل نوع ليُطبع بلغة كل عميل.

| المستوى | أيام التأخير | النبرة | الرسوم |
| --- | --- | --- | --- |
| التذكير الأول | 7 | تذكير ودي | لا يوجد |
| التذكير الثاني | 21 | حازم مع إرفاق كشف حساب | لا يوجد |
| الإنذار النهائي | 45 | إنذار نهائي قبل تعليق الحساب | رسوم إدارية إن اتُّفق عليها في العقد |

## إنشاء مطالبة

**لفاتورة واحدة**: افتح فاتورة مبيعات متأخرة وانقر **إنشاء › مطالبة**.

**لفواتير كثيرة**: افتح تقرير **الذمم المدينة**، وصفِّ الفواتير المتأخرة، وحددها وأنشئ المطالبات دفعة واحدة.

في المطالبة:

1. تحقق من **نوع المطالبة** الذي يحدد الخطاب والرسوم.
2. راجع جدول **المدفوعات المتأخرة**: الفاتورة وتاريخ الاستحقاق وأيام التأخير والمستحق والفائدة.
3. تحقق من الإجماليات: المستحق والرسوم والفائدة والإجمالي الكلي.
4. اعتمد وانقر **بريد إلكتروني** لإرسالها.

@@ pos | نقاط البيع
@summary شغّل كاونترات صالات العرض والمتاجر: ملفات نقاط البيع والبيع والمدفوعات والمرتجعات والعمل دون اتصال وإقفال نهاية اليوم والمحاسبة خلفها.

**نقطة البيع** شاشة سريعة مناسبة للمس لمبيعات الكاونتر في صالات العرض والمتاجر وكاونترات التجارة وقطع الغيار، تنشئ فواتير نقاط البيع وتستلم النقد والبطاقات وتطبع الإيصالات وتجمع كل شيء في دفاترك نهاية اليوم.

:::note قبل أن تبدأ
- أعدّ **مستودع** المتجر بمخزونه.
- أنشئ **قائمة أسعار تجزئة** بأسعار شاملة الضريبة.
- أعدّ [طرق الدفع](/accounting/mode-of-payment) للنقد والبطاقة.
- جهّز [تنسيق طباعة](/getting-started/printing) للإيصال بتخطيط الفاتورة الضريبية المبسطة.
- اربط طابعة الإيصالات ودرج النقد وماسح الباركود إن كنت تستخدمها.
:::

## ملفات نقاط البيع

يصف **ملف نقطة البيع** كاونتراً أو متجراً واحداً: ماذا يبيع ومن أين وبأي سعر وكيف يستلم الدفع.

| الحقل | وظيفته |
| --- | --- |
| الشركة والمستودع | مصدر المخزون |
| العميل | العميل النقدي الافتراضي، مثل "عميل نقدي – ديرة" |
| قائمة الأسعار والعملة | الأسعار المعروضة عند الكاونتر |
| المدفوعات | طرق الدفع المسموحة مع تعيين إحداها افتراضية |
| ينطبق على المستخدمين | أمناء الصندوق الذين يمكنهم استخدام الملف |
| مجموعات الأصناف / العملاء | تقييد ما يُباع ولمن |
| قالب الضرائب والرسوم | عادةً ضريبة 5% مشمولة في السعر |
| تنسيق الطباعة والترويسة | تخطيط الإيصال |
| السماح بتغيير الخصم / السعر | ما إذا كان أمناء الصندوق يغيّرون الأسعار |
| إخفاء الأصناف غير المتوفرة | يعرض المتوفر فقط |
| التحقق من المخزون عند الحفظ | يمنع بيع أصناف دون مخزون |
| حساب الشطب وحده | الفروقات الصغيرة المشطوبة عند الدفع |
| مركز التكلفة | لربح الفرع |

!fig ملف نقطة بيع مع المستودع وطرق الدفع وتنسيق الطباعة

## فتح الكاونتر

1. افتح **نقطة البيع**.
2. اختر ملف نقطة البيع.
3. أدخل **الرصيد الافتتاحي** لكل طريقة دفع، وعادةً عهدة النقد.
4. انقر **اعتماد**، فيسجّل **قيد افتتاح نقطة البيع** بداية الجلسة.

## البيع

1. امسح الباركود أو ابحث عن الأصناف بالاسم أو الرمز، وانقر بطاقة الصنف لإضافته.
2. غيّر الكمية أو الخصم أو السعر إن سمح ملفك.
3. اختر عميلاً أو أبقِ العميل النقدي، وللعملاء من الشركات المسجلين اختر العميل أو أنشئه برقمه الضريبي لتُطبع فاتورة ضريبية كاملة.
4. انقر **الدفع** وأدخل الدفعة: نقداً (مع احتساب الباقي) أو بطاقة أو كليهما.
5. استبدل [نقاط الولاء](/accounting/loyalty-program) أو طبّق قسيمة إن وُجدت.
6. انقر **إتمام الطلب**، فيُطبع الإيصال وتُفرغ السلة.

!fig شاشة نقطة البيع مع الأصناف والسلة وأزرار الدفع

## المرتجعات والاستبدال

1. افتح **الطلبات الأخيرة** وابحث عن الإيصال بالرقم أو العميل أو التاريخ.
2. انقر **مرتجع** واختر الأصناف والكميات.
3. أعد المبلغ بالطريقة الأصلية، أو أصدر إشعاراً دائناً يستخدمه العميل لاحقاً.

للاستبدال عالج المرتجع ثم بيعاً جديداً.

## العمل دون اتصال

إذا انقطع الإنترنت تستمر نقطة البيع في العمل، وتُحفظ الفواتير على الجهاز وتُزامَن تلقائياً عند عودة الاتصال، فلا تمسح ذاكرة المتصفح أثناء انتظار الفواتير للمزامنة.

## إقفال اليوم

1. انقر **إقفال نقطة البيع** من القائمة.
2. يعرض **قيد إقفال نقطة البيع** المبالغ المتوقعة لكل طريقة دفع.
3. اعدّ النقد، وأدخل إجمالي البطاقات من تقرير تسوية الجهاز، وأدخل أي فرق مع سببه.
4. اعتمد، فينشئ DocFlow **سجل دمج فواتير نقاط البيع** الذي يجمع فواتير الجلسة في فواتير مبيعات مجمّعة ويرحّلها إلى الأستاذ.

## ما يحدث خلف الكواليس

خلال اليوم تحدّث فواتير نقاط البيع المخزون فوراً لكنها لا ترحّل إلى دفتر الأستاذ العام منفردة، وعند الإقفال ترحّل فاتورة المبيعات المجمّعة:

| الحساب | مدين | دائن |
| --- | --- | --- |
| النقدية – صالة عرض ديرة | 8,400 | |
| تسوية البطاقات | 12,600 | |
| مبيعات البضائع | | 20,000 |
| ضريبة المخرجات 5% | | 1,000 |

وتُجمع المرتجعات في إشعار دائن بالطريقة نفسها.

:::uae الفواتير الضريبية المبسطة والكاملة
يمكن أن تكون إيصالات العملاء النقديين فواتير ضريبية مبسطة، وعندما يطلب عميل من الشركات المسجلين فاتورة ضريبية كاملة، اختره عميلاً قبل الدفع ليتضمن الإيصال الرقمين الضريبيين والبيانات الكاملة.
:::

## مشكلات شائعة

:::details "الصنف غير متوفر في المستودع"
لا يوجد مخزون في مستودع الملف، فانقل مخزوناً إلى المتجر، أو عطّل **التحقق من المخزون عند الحفظ** فقط إن سمحت سياستك بالبيع الزائد.
:::

:::details "قيد افتتاح نقطة البيع مفقود"
يجب على أمين الصندوق فتح جلسة قبل البيع، فافتحها أو أقفل جلسة قديمة تُركت مفتوحة من يوم سابق.
:::

:::details عدّ النقد ناقص أو زائد
ابحث عن مدفوعات بطاقة سُجّلت نقداً، ومرتجعات لم تُدخل، ومبالغ العهدة، وسجّل الفرق في قيد الإقفال مع سببه.
:::

@@ deferred-revenue | الإيرادات والمصروفات المؤجلة
@summary اعترف بالإيرادات والتكاليف في الأشهر التي تخصها، للعقود السنوية والاشتراكات والرخص والتأمين المدفوعة مقدماً.

| الحالة | النوع |
| --- | --- |
| عقود صيانة سنوية مفوترة مقدماً | إيراد مؤجل |
| اشتراكات برمجيات أو دعم مفوترة سنوياً | إيراد مؤجل |

## الإعداد

1. أنشئ حساب التزام **إيرادات مؤجلة** وحساب أصل **مصروفات مدفوعة مقدماً**.
2. في كل صنف معني، حدد **تفعيل الإيراد المؤجل** (أو المصروف)، واختر الحساب وعدد الأشهر الافتراضي.
3. في [إعدادات الحسابات](/accounting/accounts-settings)، حدد **معالجة قيود المحاسبة المؤجلة تلقائياً**.

## الاستخدام في الفواتير

1. في سطر فاتورة المبيعات أو المشتريات يُنسخ تحديد التأجيل من الصنف.
2. عيّن **تاريخ بدء الخدمة** و**تاريخ انتهائها**.
3. اعتمد، فيذهب المبلغ كاملاً إلى الحساب المؤجل.
4. في نهاية كل شهر يرحّل DocFlow قيداً ينقل حصة ذلك الشهر إلى الإيرادات أو المصروفات حسب الأيام أو الأشهر.

## المعالجة اليدوية

إذا كانت المعالجة التلقائية معطّلة أو احتجت إلى اللحاق، استخدم **معالجة المحاسبة المؤجلة**: اختر النوع (إيراد أو مصروف) ونطاق التواريخ والشركة ثم اعتمد.

## ما يحدث خلف الكواليس

عقد صيانة بقيمة 180,000 درهم مفوتر في 1 يناير زائد الضريبة:

| التاريخ | مدين | دائن |
| --- | --- | --- |
| 1 يناير | المدينون 189,000 | الإيرادات المؤجلة 180,000؛ ضريبة المخرجات 9,000 |
| 31 يناير ونهاية كل شهر | الإيرادات المؤجلة 15,000 | إيرادات الصيانة 15,000 |

:::uae الضريبة لا تُؤجَّل
تستحق الضريبة في تاريخ التوريد، عادةً تاريخ الفاتورة أو الدفع، لا على مدى فترة الخدمة، فالإيراد أو المصروف وحده يُوزَّع.
:::

## مشكلات شائعة

:::details لم تُرحَّل القيود الشهرية

:::

أصدر إشعاراً دائناً للأشهر غير المستخدمة بتواريخ الخدمة نفسها للفترة المتبقية، فيعكس DocFlow الرصيد المؤجل المتبقي.
:::

2. سمِّ الخطة، مثل "تقنية معلومات مُدارة – قياسية".
3. اختر **الصنف** و**تحديد السعر** (سعر ثابت أو قائمة أسعار) و**التكلفة**.
4. عيّن **دورة الفوترة** (يوم أو أسبوع أو شهر أو سنة) و**عدد الدورات**، مثل كل 3 أشهر.
5. اربط اختيارياً **بوابة دفع** ليمكن دفع الفواتير إلكترونياً.

## إنشاء اشتراك

1. انتقل إلى **المحاسبة › الاشتراك › جديد**.
2. اختر **نوع الطرف** (عميل) و**الطرف**.
3. عيّن **تاريخ البدء** و**فترة تجريبية** اختيارية و**تاريخ انتهاء** اختيارياً.
4. أضف الخطط والكميات.
5. اختر **إنشاء الفاتورة في**: بداية كل فترة أو نهايتها.
6. عيّن **أيام حتى الاستحقاق** والضرائب وأي خصم إضافي.
7. حدد **اعتماد الفاتورة** لاعتماد الفواتير تلقائياً، أو اتركه لمراجعتها أولاً.
8. احفظ.

!fig اشتراك بخطة شهرية وتاريخ الفاتورة التالية

## التغييرات خلال الاشتراك

| التغيير | الطريقة |
| --- | --- |
| ترقية أو إضافة خطة | أضف الخطة، ومع **التناسب** تُحتسب الفترة الأولى بالتناسب |
| الإيقاف المؤقت | غير مدعوم مباشرة، فألغِ وابدأ اشتراكاً جديداً |
| الإلغاء | انقر **إلغاء الاشتراك** واختر ما إذا كنت تفوتر الفترة الجزئية الأخيرة |
| توقف العميل عن الدفع | بعد فترة السماح يصبح الاشتراك **غير مسدد** أو يُلغى حسب الإعدادات |

@@ inter-company | المعاملات بين الشركات
@summary سجّل المبيعات والمشتريات وإعادة تحميل التكاليف بين شركات مجموعتك، وأبقِ الأرصدة متطابقة واستبعدها في تقارير المجموعة.

تتعامل مجموعات إماراتية كثيرة بين شركاتها: شركة منطقة حرة تستورد وتبيع لشركتها الشقيقة في البر الرئيسي، أو مكتب رئيسي يعيد تحميل التكاليف المشتركة على الشركات التابعة. يجب أن يسجّل الطرفان كل معاملة، وأن تستبعدها تقارير المجموعة.

## الإعداد

1. في **العميل** الذي يمثل الشركة الشقيقة، حدد **عميل داخلي** واختر الشركة التي يمثلها في **يمثل الشركة**، وأدرج في **مسموح بالتعامل مع** الشركات التي يمكنها البيع له.
2. في **المورد** الذي يمثل الشركة الشقيقة، حدد **مورد داخلي** وعيّن الحقول نفسها.
3. أنشئ حسابي **ذمم مدينة بين الشركات** و**ذمم دائنة بين الشركات** في كل شركة إن أردت فصل هذه الأرصدة.

## المبيعات والمشتريات بين الشركات

1. في الشركة البائعة أنشئ فاتورة مبيعات للعميل الداخلي واعتمدها.
2. انقر **إنشاء › فاتورة مشتريات بين الشركات**، فتُفتح مسودة في الشركة المشترية بالأصناف والأسعار والضرائب نفسها مرتبطة بفاتورة المبيعات.
3. تتحقق الشركة المشترية من الضرائب وحسابات المصروفات أو المخزون وتعتمد.

ويعمل المسار نفسه للأوامر: أمر بيع للعميل الداخلي يمكنه إنشاء أمر شراء مطابق.

!fig فاتورة مشتريات بين الشركات مُنشأة من فاتورة المبيعات المطابقة

## نقل المخزون بين الشركات

إذا انتقلت البضائع فعلياً بين مستودعات الشركتين، فاستخدم **تحديث المخزون** في الفاتورتين، أو أزواج إذن التسليم وإيصال الاستلام، ويكون التقييم في الشركة المشترية بسعر التحويل لا بتكلفة البائع.

## إعادة التحميل والقروض: قيود بين الشركات

للتكاليف المشتركة ورسوم الإدارة والقروض:

1. أنشئ **قيد يومية** بـ**نوع القيد = قيد يومية بين الشركات**.
2. أدخل صفوف الشركة الأولى واعتمد.
3. انقر **إنشاء قيد يومية بين الشركات**، فيُفتح قيد مطابق في الشركة الأخرى.

## مطابقة أرصدة المجموعة

في نهاية كل شهر يجب أن تساوي الذمم المدينة في شركة الذمم الدائنة في الأخرى، فشغّل الذمم المدينة لدى البائع والدائنة لدى المشتري مصفّيين حسب الطرف الداخلي، وغالباً ما تكون الفروقات مستندات في الطريق أو أسعار صرف مختلفة.

## تقارير المجموعة

شغّل **القوائم المالية الموحدة** للشركة الأم، ويجب استبعاد المبيعات والمشتريات والأرصدة بين الشركات، إما بتصفية الأطراف الداخلية أو بترحيل قيود استبعاد في شركة توحيد.

:::uae الضريبة وضريبة الشركات بين شركات المجموعة
إذا كانت الشركتان في مجموعة ضريبية واحدة، فالتوريدات بينهما خارج نطاق الضريبة عموماً، وإن كانتا مسجلتين منفصلتين تنطبق الضريبة كالمعتاد. ولأغراض ضريبة الشركات يجب أن تتبع أسعار المعاملات بين الشركات مبدأ السوق الحر. راجع [التسعير التحويلي](/uae-compliance/transfer-pricing).
:::

@@ bank-guarantee | الضمانات البنكية والاعتمادات المستندية
@summary تتبّع الضمانات التي تصدرها أو تستلمها وتأميناتها ورسومها، واحصل على تذكير قبل انتهائها.

كثيراً ما تتطلب المناقصات والعقود الحكومية وأوامر التوريد الكبيرة والدفعات المقدمة للمشاريع في الإمارات **ضماناً بنكياً**، وتُدفع الواردات كثيراً بـ**اعتماد مستندي**، ويحفظ DocFlow سجلاً لكليهما حتى لا ينتهي شيء دون انتباه.

## أنواع الضمانات

| النوع | الغرض |
| --- | --- |

| ضمان المحتجزات | يحل محل المحتجزات النقدية |
| الضمان الجمركي | يغطي الرسوم على الواردات المؤقتة |

## تسجيل ضمان

5. أدخل **المبلغ** و**تاريخ البدء** و**الصلاحية بالأيام** و**تاريخ الانتهاء**.
6. أدخل **رقم الضمان البنكي** واسم المستفيد وأي تأمين.
7. أرفق الضمان واعتمد.

@@ statement-of-accounts | كشوف حسابات العملاء
@summary أرسل للعملاء كشوفاً واضحة، واحداً تلو الآخر أو تلقائياً كل شهر، بالعربية أو الإنجليزية.

يعرض كشف الحساب للعميل ما اشتراه وما دفعه وما زال مستحقاً عليه، والكشوف المنتظمة تقلل النزاعات وتسرّع التحصيل.

## كشف واحد

1. شغّل **دفتر الأستاذ العام** مصفّى بنوع الطرف = عميل والعميل للفترة، وحدد **التجميع حسب القسيمة (موحد)** لعرض نظيف.
2. أو شغّل **الذمم المدينة** مصفّى حسب العميل، فيعرض الفواتير المفتوحة بأعمارها.
3. اطبع بترويستك أو أرسل بالبريد مباشرة من التقرير.

## كشوف لعملاء كثيرين

استخدم **معالجة كشوف الحساب**:

1. انتقل إلى **المحاسبة › معالجة كشوف الحساب › جديد**.
2. اختر **الشركة** و**التقرير** (دفتر الأستاذ العام أو الذمم المدينة) والفترة.
3. أضف العملاء فرادى أو حسب مجموعة العملاء أو المنطقة أو المندوب.
4. اختر عوامل التصفية كالعملة ومركز التكلفة وما إذا كنت تتضمن الأعمار.
5. عيّن **موضوع الرسالة** و**نصها** مع إدراج اسم العميل.
6. اختر **الترويسة** والاتجاه وما إذا كنت تضمّن جدول ملخص.
7. حدد **تفعيل الإرسال التلقائي** وعيّن التكرار، مثل شهرياً في اليوم الثالث، وتاريخ البدء.
8. احفظ، وانقر **إرسال الرسائل** للإرسال الآن أو انتظر الجدول.

!fig معالجة كشوف الحساب مع العملاء وجدول الإرسال الشهري

كثيراً ما يطلب المدققون تأكيدات من كبار العملاء والموردين، فأرسل كشف نهاية السنة مع طلب قصير بتأكيد الرصيد أو الإبلاغ عن الفروقات، بالعربية والإنجليزية.
:::

@@ petty-cash | النثرية
@summary أدر عهد النثرية في المكاتب والمواقع والمستودعات بضوابط واضحة وإيصالات وإعادة تعبئة.

تغطي النثرية الإنفاق الصغير: الوقود والمواقف وتعبئة سالك والقرطاسية والشاي والمياه ورسوم البريد السريع والإصلاحات البسيطة. إنها أموال صغيرة لكنها تحتاج إلى ضوابط البنك نفسها.

## الإعداد

1. أنشئ حساب نقد لكل عهدة، مثل *النثرية – موقع مصفح*، ضمن النقد.
2. سمِّ أميناً لكل عهدة.
3. أنشئ **طريقة دفع** لكل عهدة.
4. حدد مبلغ العهدة، مثل 3,000 درهم، وحداً للدفعة الواحدة، مثل 500 درهم.

## تسجيل الإنفاق

| الإنفاق | طريقة التسجيل |
| --- | --- |
| شراء للشركة من أمين العهدة | **قيد يومية** من نوع قيد نقدي: مدين المصروف (وضريبة المدخلات إن وُجدت فاتورة ضريبية صحيحة) ودائن النثرية، مع إرفاق الإيصالات |
| شراء من مورد منتظم | فاتورة مشتريات محدد فيها **مدفوعة** بطريقة دفع النثرية |
| إنفاق الموظفين من جيوبهم | يقدّم الموظفون [مطالبة مصروفات](/hr-payroll/expense-claims) تُسترد من النثرية |

!fig قيد نقدي لمصروفات الموقع مع الإيصالات المرفقة

## إعادة التعبئة (نظام السلفة المستديمة)

عندما تقل العهدة، يعدّ الأمين قائمة بالإنفاق منذ آخر تعبئة مع الإيصالات، فتراجعها الحسابات وتحوّل الإجمالي من البنك إلى النثرية، فتعود العهدة إلى مبلغها الثابت.

## الضوابط التي يتوقعها المدققون

- أمين واحد لكل عهدة يُذكر اسمه في الحساب.
- جرد نقدي مفاجئ مرة كل ربع سنة على الأقل، مسجل وموقّع.
- لا دفعة فوق الحد دون اعتماد.
- إيصالات مرفقة بكل قيد.
- مطابقة رصيد النثرية مع الأستاذ في نهاية الشهر.

:::uae استرداد الضريبة على الإيصالات الصغيرة
لا تُسترد ضريبة المدخلات إلا بفاتورة ضريبية صحيحة، وكثير من الإيصالات الصغيرة فواتير ضريبية مبسطة، فسجّل الضريبة فقط عندما يظهر في الإيصال الرقم الضريبي للمورد ومبلغ الضريبة.
:::

@@ loyalty-program | برامج الولاء
@summary كافئ العملاء المتكررين بالنقاط والفئات والاستبدال عند الكاونتر أو في الفواتير.

يمنح برنامج الولاء العملاء نقاطاً على إنفاقهم يستبدلونها خصماً لاحقاً، ويناسب صالات عرض التجزئة وكاونترات قطع الغيار والمطاعم.

## إنشاء برنامج

1. انتقل إلى **المبيعات › برنامج الولاء › جديد**.
2. اختر **فئة واحدة** أو **فئات متعددة**.
3. لكل فئة عيّن **اسم الفئة** و**الحد الأدنى للإنفاق** و**معامل الجمع** (الإنفاق مقابل النقطة، مثل 10 دراهم = نقطة).
4. عيّن **معامل التحويل**: قيمة النقطة عند الاستبدال، مثل 0.10 درهم.
5. عيّن **مدة الصلاحية (بالأيام)**.
6. اختر **حساب المصروف** و**مركز التكلفة** للنقاط المستبدلة.
7. اختر **مجموعة العملاء** أو **منطقة العملاء** التي ينطبق عليها وتواريخ الصلاحية.
8. حدد **الاشتراك التلقائي** لتسجيل العملاء تلقائياً.

| الفئة | الحد الأدنى للإنفاق | الجمع |
| --- | --- | --- |
| فضي | 0 درهم | نقطة لكل 10 دراهم |
| ذهبي | 20,000 درهم | نقطة لكل 8 دراهم |
| بلاتيني | 50,000 درهم | نقطة لكل 5 دراهم |

!fig برنامج ولاء بفئات ومعاملي الجمع والتحويل

## الاكتساب والاستبدال

- تُكتسب النقاط عند اعتماد فاتورة مبيعات أو فاتورة نقطة بيع بناءً على المبلغ الصافي.
- للاستبدال حدد **استبدال نقاط الولاء** في الفاتورة أو عند الدفع في نقطة البيع وأدخل النقاط، فتُطبَّق قيمتها كخصم.
- تعرض قائمة **قيود نقاط الولاء** كل اكتساب واستبدال لكل عميل.

## ما يحدث خلف الكواليس

عند استبدال نقاط بقيمة 50 درهماً في بيع، يخفض الاستبدال ما يدفعه العميل ويُحمَّل على حساب مصروف الولاء، فتظهر تكلفة البرنامج.

:::uae الضريبة على النقاط المستبدلة
تُحتسب الضريبة عادةً على السعر الذي يدفعه العميل فعلاً بعد الاستبدال، فأكّد المعالجة لبرنامجك مع مستشارك الضريبي.
:::

@@ shipping-rules | قواعد الشحن
@summary أضف رسوم التوصيل تلقائياً حسب قيمة الطلب أو الوزن أو الوجهة.

## إنشاء قاعدة

1. انتقل إلى **المبيعات › قاعدة الشحن › جديد**.
2. أدخل عنواناً يُطبع في المستندات، مثل "التوصيل – الإمارات الشمالية".
3. اختر **نوع قاعدة الشحن**: بيع أو شراء أو كليهما.
4. اختر **الاحتساب بناءً على**: صافي الإجمالي أو صافي الوزن أو ثابت.
5. أضف الشروط بـ**من قيمة** و**إلى قيمة** و**مبلغ الشحن**.
6. قيّدها بدول معينة عند الحاجة.
7. اختر **حساب الشحن** (إيرادات للبيع) ومركز التكلفة.

| القاعدة | الشرط | الرسوم |
| --- | --- | --- |
| دبي والشارقة وعجمان | صافي إجمالي أقل من 2,000 درهم | 150 درهماً |
| دبي والشارقة وعجمان | صافي إجمالي 2,000 درهم فأكثر | مجاناً |
| أبوظبي والعين | أي طلب | 300 درهم |
| الإمارات الشمالية | أي طلب | 350 درهماً |
| الأصناف الثقيلة | صافي وزن فوق 500 كجم | 600 درهم |

!fig قاعدة شحن بشروط صافي الإجمالي والرسوم

في المستند اختر القاعدة في **قاعدة الشحن**، أو عيّنها افتراضية للعميل، فتظهر الرسوم كصف في جدول الضرائب والرسوم.

:::uae رسوم التوصيل خاضعة للضريبة
رسوم التوصيل التي تُعد جزءاً من بيع خاضع تخضع لنسبة 5% مثل البضاعة، فتأكد من احتساب صف الضريبة على الإجمالي شاملاً صف الشحن.
:::

@@ opening-balances | الأرصدة الافتتاحية والترحيل
@summary انتقل من نظامك القديم أو جداول البيانات إلى DocFlow بأرصدة وفواتير مفتوحة ومخزون وأصول صحيحة من اليوم الأول.

بدء التشغيل يعني نقل تاريخك إلى DocFlow حتى يطابق أول ميزان مراجعة دفاترك القديمة تماماً، والطريقة الأسلم هي تحميل البنود المفتوحة بالتفصيل وكل ما عداها كأرصدة، بتاريخ اليوم السابق لبدء التشغيل.

:::note قبل أن تبدأ
- اختر تاريخ بدء التشغيل، ويفضّل أول الشهر أو، الأفضل، أول السنة المالية.
- أقفل الدفاتر القديمة للفترة السابقة واحصل على ميزان مراجعة نهائي وأعمار الذمم المدينة والدائنة وقائمة المخزون وسجل الأصول الثابتة.
- أعدّ دليل الحسابات ومراكز التكلفة والعملاء والموردين والأصناف في DocFlow أولاً.
:::

## ما الذي تحمّله وكيف

| الرصيد | طريقة التحميل | التفصيل المحفوظ |
| --- | --- | --- |
| أرصدة العملاء | **أداة إنشاء الفواتير الافتتاحية** (مبيعات) | كل فاتورة غير مسددة برقمها وتاريخها وتاريخ استحقاقها |
| أرصدة الموردين | أداة إنشاء الفواتير الافتتاحية (مشتريات) | كل فاتورة غير مسددة |
| الدفعات المقدمة من العملاء وللموردين | قيود دفع بتاريخ اليوم السابق لبدء التشغيل غير مخصصة | كل دفعة مقدمة |
| المخزون | **تسوية مخزون** بغرض *مخزون افتتاحي* | الكمية والقيمة لكل صنف ومستودع ودفعة |
| الأصول الثابتة | أصول محدد فيها **أصل قائم** | التكلفة وتاريخ الشراء ومجمع الإهلاك |
| البنك والنقد والضريبة والمستحقات والقروض وحقوق الملكية | **قيد يومية** محدد فيه **افتتاحي** | أرصدة الحسابات |
| الشيكات غير المصفاة | قيود دفع بتواريخ الشيكات الأصلية | للتسوية البنكية |

## استخدام حساب افتتاحي مؤقت

يرحّل كل مستند افتتاحي طرفه الآخر إلى حساب **افتتاحي مؤقت**، وعند تحميل كل شيء يجب أن يكون ذلك الحساب صفراً، لأن البنود التفصيلية والقيد الافتتاحي معاً يساويان ميزان المراجعة القديم.

1. حمّل الفواتير المفتوحة، فيتكون رصيد في الحساب المؤقت.
2. حمّل المخزون والأصول، فيضاف إليه المزيد.
3. رحّل القيد الافتتاحي لكل الحسابات المتبقية مع الرقم الموازن إلى الحساب المؤقت.
4. تحقق من أن الحساب الافتتاحي المؤقت صفر تماماً.

!fig ميزان المراجعة في يوم بدء التشغيل مع الحساب الافتتاحي المؤقت صفراً

## أداة إنشاء الفواتير الافتتاحية

1. انتقل إلى **المحاسبة › أداة إنشاء الفواتير الافتتاحية**.
2. اختر الشركة و**نوع الفاتورة** (مبيعات أو مشتريات).
3. أضف الصفوف أو استوردها: الطرف وتاريخ الترحيل (تاريخ الفاتورة الأصلي) وتاريخ الاستحقاق والمبلغ المستحق ورقم الفاتورة في الملاحظات.
4. انقر **إنشاء الفواتير**.

تُنشأ الفواتير مقابل صنف افتتاحي مؤقت دون ضريبة، لأن ضريبتها أُبلغ عنها في النظام القديم.

## التحقق من الترحيل

- ميزان المراجعة في تاريخ بدء التشغيل يساوي ميزان الإقفال في النظام القديم.
- أعمار الذمم المدينة والدائنة تطابق الأعمار القديمة عميلاً عميلاً.
- رصيد المخزون يطابق قائمة المخزون، وتقرير **مقارنة قيمة المخزون والحسابات** لا يُظهر فرقاً.
- سجل الأصول الثابتة يطابق التكلفة وصافي القيمة الدفترية.
- الحساب الافتتاحي المؤقت صفر.

:::tip رحّل على نسخة تجريبية أولاً
نفّذ ترحيلاً تجريبياً كاملاً على موقع تجريبي، وصحّح جداول البيانات ثم كرر على الموقع الفعلي، فالتجربة توفر عادةً أياماً من التصحيحات.
:::

@@ common-party-accounting | العملاء الذين هم موردون أيضاً
@summary قاصّ ما يدين به طرف لك مقابل ما تدين به له دون تحريك الأموال مرتين.

تشتري بعض المنشآت من الشركة نفسها وتبيع لها، مثل موزع يبيعك قطع غيار ويشتري منتجاتك التامة، فبدلاً من أن يدفع كل منكما للآخر كاملاً يمكنكما تسوية الفرق.

## الإعداد

1. حدد **تفعيل محاسبة الطرف المشترك** في [إعدادات الحسابات](/accounting/accounts-settings).
2. أنشئ **ربط طرف** بين سجلي العميل والمورد للشركة نفسها.

## آلية العمل

عند اعتماد فاتورة مبيعات للعميل، ينشئ DocFlow تلقائياً قيداً ينقل المبلغ من ذمة العميل المدينة إلى ذمة المورد المرتبط الدائنة (أو العكس لفاتورة المشتريات)، ويظهر الرصيد الصافي للطرف في جانب المورد.

## التسوية بقيد مقاصة

دون الإعداد التلقائي يمكنك التسوية يدوياً:

| الحساب | مدين | دائن |
| --- | --- | --- |
| الدائنون – الخليج لتجارة القطع | 15,000 | |
| المدينون – الخليج لتجارة القطع | | 15,000 |

اربط كل صف بالفاتورة التي يسددها عبر **نوع المرجع** و**اسم المرجع**، واتفق على المقاصة كتابياً مع الشركة الأخرى.

!fig قيد مقاصة يسوّي رصيد عميل مقابل رصيد مورد للشركة نفسها

@@ payment-order | المدفوعات الجماعية للموردين
@summary ادفع لموردين كثيرين دفعة واحدة وارفع ملف دفع واحداً إلى بنكك.

الدفع للموردين تحويلاً تلو الآخر في الخدمات المصرفية الإلكترونية بطيء وعرضة للأخطاء، و**أمر الدفع** يجمع المدفوعات المعتمدة في دفعة واحدة للبنك.

## الخطوات

1. اعتمد الفواتير للدفع، إما بإنشاء **طلبات دفع** (صادرة) من فواتير المشتريات أو باختيار الفواتير مباشرة.
2. انتقل إلى **المحاسبة › أمر الدفع › جديد**.
3. اختر **الحساب البنكي للشركة** الذي سيدفع.
4. انقر **جلب القيود من › طلب الدفع** (أو قيد الدفع) وحدد المدفوعات المراد تضمينها.
5. اعتمد، فيُنشأ قيد دفع لكل مورد أو يُربط.
6. نزّل ملف البنك بصيغة الدفع الجماعي لبنكك وارفعه إلى الخدمات المصرفية الإلكترونية.
7. عند تأكيد البنك تُصفّى المدفوعات في التسوية البنكية.

!fig أمر دفع يجمع مدفوعات الموردين لرفع بنكي واحد

## دورة دفع أسبوعية

| اليوم | الخطوة |
| --- | --- |
| الاثنين | مراجعة الذمم الدائنة وإدراج الفواتير المستحقة هذا الأسبوع |
| الثلاثاء | يعتمد المدير المالي طلبات الدفع |
| الأربعاء | إنشاء أمر الدفع ورفع الملف |
| الخميس | يفوّض البنك الدفعات وتُرسل إشعارات الدفع للموردين |

:::warning تحقق من البيانات المصرفية
تأتي أرقام IBAN للموردين من سجلات حساباتهم البنكية، ويجب التحقق هاتفياً من أي تغيير في البيانات المصرفية للمورد واعتماده قبل دورة الدفع التالية.
:::
